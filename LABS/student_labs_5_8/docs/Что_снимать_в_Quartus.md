# Что снять руками в Quartus для ЛР5-8

Этот файл нужен, если преподаватель просит не только готовые схемы из отчетов, но и реальные скриншоты из Quartus. В отчетах сами названия служебных окон писать не надо: формулируй нейтрально как "схема верхнего уровня проекта" и "временная диаграмма проверки".

## Общий порядок

1. Открой `.qpf` нужной лабораторной:
   - ЛР5: `lab5_alu/quartus/lab5_alu.qpf`
   - ЛР6: `lab6_stack/quartus/lab6_stack.qpf`
   - ЛР7: `lab7_bus_arbiter/quartus/lab7_bus_arbiter.qpf`
   - ЛР8: `lab8_cache/quartus/lab8_cache.qpf`
2. Выполни `Processing -> Start Compilation`.
3. Сними скриншот успешной сборки или окна `Compilation Report -> Flow Summary`.
4. Открой схемное представление верхнего уровня и сними скриншот так, чтобы были видны названия входов, выходов и диагностических линий.
5. Для временной диаграммы можно использовать готовые дампы из `sim/vcd/` или создать `.vwf`:
   - `File -> New -> Verification/Debugging Files -> Vector Waveform File`;
   - добавить пины через `Edit -> Insert -> Insert Node or Bus`;
   - задать значения входов по таблицам ниже;
   - выполнить функциональное моделирование.

Если преподаватель просит конкретное семейство ПЛИС, его можно выбрать вручную через `Assignments -> Device` и пересобрать проект. Логика устройств не использует семействозависимые мегаблоки, поэтому алгоритм работы от выбора семейства не меняется.

## ЛР5. АЛУ

Что снять:

- схему верхнего уровня с входами команды, операндов и выходами результата/флагов;
- при раскрытии внутренней структуры показать ветви `CMP`, `NOR`, `SRA`, мультиплексор результата и блок флагов;
- временную диаграмму трех операций.

Сигналы для временной диаграммы:

| Сигнал | Что показать |
|---|---|
| `cmd_opcode_alu_operation_i[7..0]` | `03h`, `04h`, `05h` |
| `operand_a_from_register_i[15..0]` | `1234`, `2222`, `0010`, `0F0F`, `8001` |
| `operand_b_from_memory_or_reg_i[15..0]` | `0020`, `2222`, `0020`, `F0F0`, `0000` |
| `result_y_to_register_file_o[15..0]` | результат выбранной операции |
| `flag_z_zero_result_o` | равенство при `CMP` и нулевой результат |
| `flag_s_negative_result_o` | отрицательный признак |
| `flag_c_carry_or_shift_out_o` | заем при `CMP` или вытолкнутый бит при `SRA` |
| `flag_o_overflow_o` | переполнение для операции сравнения |

Контрольные точки:

- `CMP 1234h,0020h` - результат сравнения больше нуля;
- `CMP 2222h,2222h` - `Z=1`;
- `CMP 0010h,0020h` - фиксируется заем;
- `NOR 0F0Fh,F0F0h -> 0000h`;
- `SRA 8001h -> C000h`, `C=1`.

## ЛР6. Стек

Что снять:

- схему верхнего уровня с командой, входами данных, выходом чтения, указателем и флагами;
- внутренний стековый массив и блок контроля границ;
- временную диаграмму `PUSH`, `POP`, `PUSH_ALU`, `overflow`, `underflow`.

Сигналы:

| Сигнал | Что показать |
|---|---|
| `clock_i`, `reset_i` | такт и сброс |
| `stack_command_idle_push_pop_i[1..0]` | `01` PUSH, `10` POP, `11` PUSH_ALU |
| `data_from_register_file_i[15..0]` | `1111`, `2222`, затем заполнение |
| `alu_result_for_push_i[15..0]` | `000F` |
| `data_popped_to_register_file_o[15..0]` | результат POP |
| `stack_pointer_current_value_o[2..0]` | `7 -> 0 -> 1 -> ... -> 6 -> 7` |
| `status_stack_empty_o`, `status_stack_full_o` | пустой/полный стек |
| `error_push_to_full_stack_o`, `error_pop_from_empty_stack_o` | ошибки границ |

Ключевая фраза для защиты: указатель показывает последнюю занятую ячейку. При добавлении первого слова используется ячейка `0`, затем вершина перемещается к следующему индексу. После чтения последнего слова указатель возвращается в служебное пустое состояние `7`.

## ЛР7. Арбитраж шин

Что снять:

- схему верхнего уровня с линиями запросов, разрешений, номером текущего слота и общей шиной;
- центральный арбитр и мультиплексор данных;
- временную диаграмму `REQ/GNT/BUS`.

Сигналы:

| Сигнал | Что показать |
|---|---|
| `master_bus_request_lines_o[3..0]` | независимые запросы ведущих |
| `arbiter_bus_grant_lines_o[3..0]` | one-hot разрешение шины |
| `current_time_quantum_slot_o[1..0]` | текущий слот `0,0,1,1,2,2,3,3...` |
| `shared_data_bus_to_slave_o[15..0]` | данные выбранного ведущего |
| `slave_latched_data_from_bus_o[15..0]` | данные, зафиксированные ведомым |
| `slave_data_valid_strobe_o` | прием данных ведомым |

Контроль: одновременно активен не более один бит разрешения. Если в текущем слоте есть запрос, шина отдается соответствующему ведущему; если запроса нет, шина свободна до следующего кванта.

## ЛР8. Кэш-память

Что снять:

- схему верхнего уровня с запросом CPU, адресом, данными, признаками попадания/промаха и интерфейсом основной памяти;
- внутренние блоки: разбор адреса, массив строк, сравнение тега, контроллер обращения к памяти;
- временную диаграмму чтения, попадания, промаха, сквозной записи и замещения строки.

Сигналы:

| Сигнал | Что показать |
|---|---|
| `cpu_cache_request_i`, `cpu_write_enable_i` | запрос CPU, чтение/запись |
| `cpu_address_tag_set_i[15..0]` | `0010`, `0018` |
| `cpu_write_data_to_cache_i[15..0]` | `ABCD` для сквозной записи |
| `cpu_read_data_from_cache_o[15..0]` | `1110`, `ABCD`, значение после замещения |
| `cpu_cache_response_ready_o` | готовность ответа |
| `cache_hit_signal_o`, `cache_miss_signal_o` | попадание/промах |
| `memory_request_from_cache_debug_o`, `memory_write_enable_debug_o` | обращение к основной памяти |
| `memory_address_debug_o[15..0]`, `memory_data_debug_o[15..0]` | адрес и данные основной памяти |

Последовательность:

1. `R[0010]` - первый промах, загрузка из основной памяти.
2. `R[0010]` - попадание.
3. `W[0010]=ABCD` - сквозная запись и обновление строки.
4. `R[0018]` - тот же индекс строки, другой тег, происходит замещение.
5. `R[0010]` - повторный промах после замещения; из основной памяти возвращается `ABCD`.
