Текст перед рисунком:

> На рисунке 2.x приведена структурная схема блока кэш-памяти, полученная в RTL Viewer. Кэш-память выполнена как четырехканальная ассоциативная память с 16 наборами. Для каждого way хранятся данные, тег, признак достоверности и счетчик возраста строки. При записи используется режим сквозной записи: строка кэша обновляется одновременно с записью данных в ОЗУ.

## 2. Вставить фрагмент автомата управления кэшем

Важно:

В State Machine Viewer Quartus может показывать автомат КПДП, например `dma_controller_3word:U_DMA|state_r`. Его в раздел кэша вставлять нельзя.

То, что ты нашел на схеме, подходит: желтый блок `state_r` внутри `system_core:U_SYSTEM|cache_4way_age:U_CACHE|state_r`. Справа у него видны состояния:

- `state_r.IDLE`;
- `state_r.WAIT_READ_GRANT`;
- `state_r.WAIT_READ_DATA`;
- `state_r.WAIT_WRITE_GRANT`.

Где сделать в Quartus:

1. Открой основной проект `coursework_project/quartus/coursework.qpf`.
2. `Tools -> Netlist Viewers -> RTL Viewer` или Technology Map Viewer.
3. В дереве раскрой `microcomputer_debug_top -> system_core:U_SYSTEM -> cache_4way_age:U_CACHE`.
4. Найди `state_r` через дерево `Nets` или через визуальный поиск.
5. Увеличь область так, чтобы были видны сам блок `state_r` и выходы состояний справа.
6. Сделай скрин/экспорт только этого фрагмента.

Можно также использовать готовую схему автомата, построенную по VHDL:

- `documents/images/cache_control_fsm.png`;
- `documents/graphics/Рисунок_кэш_автомат_управления.pdf`.

Подпись для скрина из Quartus:

`Рисунок 2.x - Фрагмент RTL-схемы автомата управления кэш-памятью`

Подпись для готового графа:

`Рисунок 2.x - Автомат управления кэш-памятью`

Текст перед рисунком:

> Управление кэш-памятью выполняется конечным автоматом `state_r`. В реализации используются состояния `IDLE`, `WAIT_READ_GRANT`, `WAIT_READ_DATA` и `WAIT_WRITE_GRANT`. В состоянии `IDLE` выполняется прием запроса процессора и проверка наличия данных в кэше. При промахе чтения автомат переходит к запросу данных из ОЗУ, а при записи - к состоянию сквозной записи.

Текст после рисунка:

> В состоянии `WAIT_READ_GRANT` кэш ожидает разрешение доступа к ОЗУ по сигналу `ram_grant_i`. После получения разрешения автомат переходит в `WAIT_READ_DATA`, где считанное из ОЗУ слово записывается в выбранный way и выдается процессору. В состоянии `WAIT_WRITE_GRANT` выполняется запись данных в ОЗУ, что соответствует режиму write-through. После завершения операции автомат возвращается в состояние `IDLE`.

## 4. Сделать временную диаграмму отдельного кэша

Где делать:

Создай отдельную VWF для сущности `cache_4way_age`.

В Quartus:

1. `File -> New -> Verification/Debugging Files -> Vector Waveform File`.
2. Сохрани как `cache_4way_age_wave.vwf`.
3. `Edit -> Insert -> Insert Node or Bus`.
4. `Node Finder`.
5. Filter: `Pins: all`.
6. Top-level/entity должен быть `cache_4way_age` или отдельный проект/тестовый top для кэша.
7. Добавь сигналы ниже.

Сигналы:

- `clk_i`;
- `rst_i`;
- `cpu_req_i`;
- `cpu_we_i`;
- `cpu_addr_i[15..0]`;
- `cpu_wdata_i[15..0]`;
- `cpu_rdata_o[15..0]`;
- `cpu_ready_o`;
- `hit_o`;
- `miss_o`;
- `ram_req_o`;
- `ram_we_o`;
- `ram_addr_o[15..0]`;
- `ram_wdata_o[15..0]`;
- `ram_rdata_i[15..0]`;
- `ram_grant_i`.

Что показать на диаграмме:

1. Сброс: `rst_i=1`, потом `rst_i=0`.
2. Первое чтение `cpu_addr_i=0020h`, `cpu_we_i=0`, `cpu_req_i=1`.
3. Ожидаемый результат: `miss_o=1`, `ram_req_o=1`, `ram_addr_o=0020h`.
4. Подать `ram_grant_i=1`, `ram_rdata_i=8001h`.
5. Ожидаемый результат: `cpu_ready_o=1`, `cpu_rdata_o=8001h`.
6. Повторное чтение `0020h`.
7. Ожидаемый результат: `hit_o=1`, `ram_req_o=0`, данные идут из кэша.
8. Запись по адресу `0020h` или `0030h`: `cpu_we_i=1`, `cpu_wdata_i=C001h`.
9. Ожидаемый результат: `ram_we_o=1`, `ram_addr_o=0020h/0030h`, `ram_wdata_o=C001h`.

Подпись:

`Рисунок 2.x - Временная диаграмма функционального моделирования кэш-памяти`

Текст перед рисунком:

> Для проверки работы кэш-памяти выполнено функциональное моделирование отдельного блока `cache_4way_age`. На временной диаграмме показаны операции чтения при промахе, повторного чтения при попадании и записи в режиме сквозной записи.

Текст после рисунка:

> При первом обращении к адресу `0020h` кэш не содержит достоверной строки с требуемым тегом, поэтому формируется сигнал `miss_o`, выставляется запрос `ram_req_o`, а адрес передается на `ram_addr_o`. После получения разрешения `ram_grant_i` слово `8001h` считывается из ОЗУ, записывается в выбранный way и передается процессору через `cpu_rdata_o`. При повторном обращении к адресу `0020h` совпадает тег и установлен valid-бит, поэтому формируется `hit_o`, а обращение к ОЗУ не выполняется. При операции записи кэш выставляет `ram_we_o`, `ram_addr_o` и `ram_wdata_o`, что подтверждает работу в режиме сквозной записи.

## 6. Финальный вывод по подразделу

Вставь после всех рисунков:

> Разработанная кэш-память является четырехканальной множественно-ассоциативной памятью с 16 наборами. Для каждой строки хранятся данные, тег, valid-бит и счетчик возраста AGE. При чтении выполняется параллельное сравнение тегов во всех way выбранного набора. При попадании данные выдаются процессору без обращения к ОЗУ, а при промахе выполняется чтение из ОЗУ и заполнение выбранной строки кэша. При записи используется режим write-through, при котором данные одновременно обновляются в кэше и передаются в ОЗУ. Выбор строки для замещения выполняется по свободному way, а при отсутствии свободных строк - по максимальному значению AGE.
