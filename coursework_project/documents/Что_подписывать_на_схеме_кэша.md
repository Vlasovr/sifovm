# Что подписывать на структурной схеме кэша

Эта памятка для листа "Блок кэш-памяти. Схема структурная".

## Главные подписи шин

- `cpu_addr_i[15..0]` - адрес от процессора.
- `TAG = A[15..4]` - старшие 12 разрядов адреса, сравниваются с тегами.
- `SET = A[3..0]` - младшие 4 разряда адреса, выбирают один из 16 наборов.
- `cpu_wdata_i[15..0]` - данные от процессора при записи.
- `cpu_rdata_o[15..0]` - данные, возвращаемые процессору.
- `ram_addr_o[15..0]` - адрес обращения к ОЗУ.
- `ram_wdata_o[15..0]` - данные записи в ОЗУ.
- `ram_rdata_i[15..0]` - данные, считанные из ОЗУ при промахе.
- `clk_i`, `rst_i` - тактирование и сброс.

## Подписи блоков

- `ADDRESS_SPLIT` - разбиение адреса на TAG и SET.
- `cache_data_way0..3` - четыре банка данных кэша, по одному на каждый way.
- `cache_tag_way0..3` - четыре банка тегов.
- `cache_valid_way0..3` - признаки достоверности строк.
- `cache_age_way0..3` - счетчики возраста строк для алгоритма замещения.
- `tag_compare_way0..3` - сравнение TAG запроса с TAG соответствующего way.
- `HIT/MISS LOGIC` - формирование `hit_o` и `miss_o`.
- `cache_data_mux 4:1` - выбор данных из way, в котором найден hit.
- `victim_select` - выбор way для замещения: сначала invalid, иначе максимальный AGE.
- `CACHE_CONTROL FSM` - автомат управления чтением, промахом, заполнением и записью.
- `RAM_INTERFACE / WRITE-THROUGH` - обращение к ОЗУ и сквозная запись.

## Какие примитивы рисовать

Нужны только смысловые примитивы, которые объясняют работу:

- компаратор `TAG == stored TAG`;
- `AND`: `tag_equal_i AND valid_i -> way_hit_i`;
- `OR`: `way_hit0..3 -> cache_hit`;
- `NOT`: `cache_miss = NOT cache_hit`;
- `MUX 4:1`: выбор данных `data_way0..3` по `hit_way`;
- декодер/выбор `way_we[3..0]`;
- блок выбора замещения `victim_select`.

Не надо переносить на лист все примитивы из Technology Map Viewer:

- отдельные D-триггеры каждого бита;
- `combout`, `regout`, `lcell`, `atom`;
- десятки однотипных регистров `data_r`, `tag_r`, `valid_r`, `age_r`;
- все страницы после разворачивания VHDL.

Для отчета нормальная схема - это RTL/структурный уровень, где видна архитектура кэша.
Technology Map Viewer нужен только как доказательство синтеза, но не как основной лист.
