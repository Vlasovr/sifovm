Комментарии к VHDL-коду проекта

Формат: сначала указано название смыслового блока, затем исходный файл, затем пояснение.
В файл включены только существенные части рабочей реализации из coursework_project/src и основные тесты из coursework_project/tb.
Архивные варианты, повторяющиеся debug-порты, стандартные library/use и однотипные port map не комментируются отдельно.


Общие параметры микро-ЭВМ

Файл: src/microcomputer_pkg.vhd

В этом пакете собраны общие константы проекта: ширина слова DATA_W = 16, ширина адреса ADDR_W = 16, число регистров общего назначения REG_COUNT = 12, глубина стека STACK_DEPTH = 7, число множеств и направлений кэша CACHE_SETS = 16 и CACHE_WAYS = 4. Пакет нужен, чтобы все модули использовали одинаковые типы и параметры.

Также здесь определены типы word_t, addr_t, reg_idx_t и массив ram256_t. Эти типы применяются в процессоре, памяти, кэше, DMA и тестбенчах.


Коды операций АЛУ и команд

Файл: src/microcomputer_pkg.vhd

В пакете заданы коды операций АЛУ: ALU_OR, ALU_NOR, ALU_SRA, ALU_INCS и служебный ALU_PASS_A. Эти коды передаются из cpu_core в alu_core.

Ниже определены коды машинных команд OP_HLT, OP_MOV_MR, OP_MOV_RM, OP_OR, OP_NOR, OP_SRA, OP_INCS, OP_PUSH, OP_POP, OP_JMP и OP_JZ. Процессор сравнивает opcode текущей команды с этими константами на этапе декодирования.


Насыщающее увеличение 2-битного счетчика

Файл: src/microcomputer_pkg.vhd

Функция sat_inc2 используется для 2-битных счетчиков, которые не должны переполняться. Если счетчик уже равен "11", он остается равным "11"; иначе увеличивается на единицу. Такая логика нужна в предсказателе переходов и в документационной модели кэша для счетчиков возраста.


Верхний модуль устройства

Файл: src/microcomputer_top.vhd

Этот модуль является внешней оболочкой проекта. Он содержит только пользовательские входы и выходы: CLK, RESET, DMA_START, DMA_VALID, DMA_DATA, HALT и DMA_DONE.

Внутри создается экземпляр system_core. Все отладочные выходы system_core в этом варианте подключены к open, потому что для обычного верхнего уровня они не нужны.


Отладочный верхний модуль

Файл: src/microcomputer_debug_top.vhd

Этот модуль повторяет обычный верхний уровень, но дополнительно выводит внутренние сигналы системы: состояние процессора, PC, IR0, IR1, регистры R1...R7, флаги, указатель стека, признаки hit/miss кэша, запросы и разрешения шины, сигналы RAM и предсказателя переходов.

Он нужен не для изменения логики устройства, а для удобного моделирования и построения временных диаграмм.


Системное ядро

Файл: src/system_core.vhd

system_core соединяет все основные узлы микро-ЭВМ: процессорное ядро cpu_core, ПЗУ команд rom_sync, кэш данных cache_4way_age, ОЗУ ram_sync, арбитр bus_arbiter_2master, DMA-контроллер dma_controller_3word и предсказатель переходов branch_predictor.

Модуль является структурным: сам почти не выполняет вычисления, а связывает сигналы между блоками и задает общую схему обмена данными.


Мультиплексирование доступа к RAM

Файл: src/system_core.vhd

RAM может использоваться двумя источниками: кэшем процессора и DMA-контроллером. Поэтому в system_core выбирается, чьи сигналы попадут на вход RAM.

Если активен grant для DMA, адрес, данные и сигнал записи берутся от DMA. Если DMA не получил шину, RAM обслуживает запрос кэша. Это реализует централизованный доступ к общей памяти данных.


Подключение процессорного ядра

Файл: src/system_core.vhd

Экземпляр U_CPU подключает cpu_core к ПЗУ команд, кэшу данных и предсказателю переходов. Через rom_addr_o и rom_en_o процессор выбирает команды из ROM, через cache_req_o/cache_we_o обращается к данным, а через bp_query_o и bp_update_o взаимодействует с предсказателем.

Отладочные выходы CPU напрямую выводятся наружу через dbg_* сигналы system_core.


Подключение ROM, кэша и RAM

Файл: src/system_core.vhd

ROM получает адрес команды от процессора и возвращает очередное слово команды. Кэш принимает запросы CPU к памяти данных и при необходимости обращается к RAM. RAM является физической моделью памяти данных, общей для кэша и DMA.

Такое разделение соответствует гарвардской организации: команды читаются из отдельного ПЗУ, а данные проходят через отдельный тракт RAM/кэш.


Автомат управления CPU

Файл: src/cpu_core.vhd

Процессорное ядро реализовано как синхронный конечный автомат state_r. В нем есть состояния сброса, выборки двух слов команды, декодирования, чтения/записи памяти, выполнения АЛУ-операций, работы со стеком, переходов и останова.

Каждое состояние соответствует отдельному микрошагу выполнения команды. Это упрощает работу с синхронными ROM/RAM, потому что после выдачи адреса требуется дождаться появления данных.


Кодирование состояний CPU для отладки

Файл: src/cpu_core.vhd

Функция state_code переводит перечислимое состояние state_t в 5-битный код. Этот код выводится через dbg_state_o и используется в моделировании, чтобы на временной диаграмме видеть текущую фазу работы процессора.

На функциональность процессора это не влияет, но сильно упрощает проверку последовательности микрошагов.


Формирование управляющих сигналов CPU

Файл: src/cpu_core.vhd

В начале architecture rtl сформированы комбинационные управляющие сигналы. Например, запись в регистровый файл разрешается в состояниях S_ALU_WRITE, S_RF_WRITE_MEM и S_RF_WRITE_POP. Запрос к кэшу активен только в состояниях S_CACHE_READ и S_CACHE_WRITE.

Такой подход отделяет сам автомат состояний от сигналов управления исполнительным трактом.


Подключение регистрового файла

Файл: src/cpu_core.vhd

Внутри CPU используется reg_file12x16_dbg. Это регистровый файл на 12 регистров по 16 бит с дополнительными выходами для просмотра содержимого регистров.

Адрес записи и адрес чтения A берутся из cur_reg_r, то есть из номера регистра, выделенного из первого слова команды.


Подключение АЛУ и регистра флагов

Файл: src/cpu_core.vhd

АЛУ получает операнды alu_a_r и alu_b_r, код операции alu_op_r и текущий флаг S. Результат alu_y может записываться обратно в регистровый файл.

Флаги Z, S, C и O записываются в flags_reg только в состоянии S_ALU_WRITE. Благодаря этому флаги меняются только после арифметико-логических команд, а не при каждом изменении входов АЛУ.


Подключение стека

Файл: src/cpu_core.vhd

Стек stack7x16 подключен к регистровому файлу: при PUSH в стек записывается значение rf_a, при POP значение stack_dout затем записывается в выбранный регистр.

Сигналы stack_push и stack_pop формируются по состояниям автомата S_STACK_PUSH и S_STACK_POP.


Сброс процессора

Файл: src/cpu_core.vhd

При rst_i = '1' процессор переходит в состояние S_RESET, очищает PC, регистры команд IR0/IR1, текущий opcode, адрес ROM и внутренние регистры АЛУ. После сброса выполнение начинается с адреса 0000h.


Выборка первого слова команды

Файл: src/cpu_core.vhd

В состоянии S_FETCH0_REQ процессор выставляет в rom_addr_r текущий PC. Затем через состояния ожидания и фиксации считывает первое слово команды в ir0_r.

Первое слово содержит код операции в старшем байте и номер регистра в младших битах.


Выборка второго слова команды

Файл: src/cpu_core.vhd

После фиксации первого слова процессор выставляет адрес PC + 1 и считывает второе слово команды в ir1_r. Второе слово используется как прямой адрес операнда, адрес записи или адрес перехода.

Так как формат команды двухсловный, обычное завершение команды увеличивает PC на 2.


Декодирование команды

Файл: src/cpu_core.vhd

В состоянии S_DECODE из ir0_r выделяется opcode_v = ir0_r(15 downto 8), а номер регистра записывается в cur_reg_r = ir0_r(7 downto 4).

Далее opcode сравнивается с константами OP_*. В зависимости от команды автомат переходит к чтению памяти, записи памяти, настройке АЛУ, работе со стеком, переходу или останову.


Команды чтения из памяти

Файл: src/cpu_core.vhd

Команды MOV adr, reg, OR reg, adr и NOR reg, adr переводят автомат в состояние S_CACHE_READ. Процессор выставляет адрес ir1_r на cache_addr_o и ждет cache_ready_i.

Если выполняется MOV adr, reg, прочитанное слово cache_rdata_i записывается в регистр. Если выполняется OR или NOR, прочитанное слово становится вторым операндом АЛУ.


Команда записи в память

Файл: src/cpu_core.vhd

Команда MOV reg, adr переводит автомат в состояние S_CACHE_WRITE. На cache_addr_o выставляется адрес ir1_r, а на cache_wdata_o подается значение выбранного регистра rf_a.

После подтверждения cache_ready_i команда считается завершенной, и процессор переходит к следующей команде.


Выполнение OR и NOR

Файл: src/cpu_core.vhd

Для OR и NOR процессор сначала читает операнд из памяти через кэш. После готовности кэша в alu_a_r записывается значение регистра, в alu_b_r - значение из памяти, а alu_op_r получает ALU_OR или ALU_NOR.

На следующем микрошаге результат АЛУ записывается в тот же регистр, а флаги обновляются.


Выполнение SRA и INCS

Файл: src/cpu_core.vhd

Команды SRA и INCS не требуют обращения к памяти. В состоянии S_ALU_SETUP_REG значение выбранного регистра помещается в alu_a_r, а alu_op_r получает ALU_SRA или ALU_INCS.

После этого в состоянии S_ALU_WRITE результат записывается обратно в регистр, а регистр флагов принимает новые значения.


Команда PUSH

Файл: src/cpu_core.vhd

При OP_PUSH автомат переходит в S_STACK_PUSH. В этом состоянии активируется stack_push, а на вход стека din_i подается значение выбранного регистра rf_a.

После одного такта процессор переходит в S_FINISH и увеличивает PC на 2.


Команда POP

Файл: src/cpu_core.vhd

При OP_POP автомат сначала переходит в S_STACK_POP, где активируется stack_pop. Затем в S_RF_WRITE_POP значение stack_dout записывается в выбранный регистр.

Разделение на два состояния нужно, потому что стек синхронный и результат чтения появляется после тактового фронта.


Обработка переходов и завершение команды

Файл: src/cpu_core.vhd

В состоянии S_BRANCH_JMP в PC сразу записывается адрес ir1_r, после чего начинается выборка новой команды.

В состоянии S_BRANCH_JZ проверяется флаг Z. Если Z = 1, PC получает адрес ir1_r; если Z = 0, PC увеличивается на 2. При обычном завершении команды S_FINISH также выполняется PC := PC + 2.


Останов процессора

Файл: src/cpu_core.vhd

Команда HLT переводит автомат в состояние S_HALT. В этом состоянии процессор остается постоянно, а выход halt_o принимает значение '1'.

Этот сигнал используется тестбенчем как признак завершения программы.


Комбинационная логика АЛУ

Файл: src/alu_core.vhd

АЛУ реализовано как комбинационный process, чувствительный к a_i, b_i, flag_s_i и op_i. Внутри process выбирается операция по op_i и формируется результат y_v.

Так как блок комбинационный, он не хранит состояние. Запоминание результата и флагов выполняется уже в cpu_core и flags_reg.


Операция OR

Файл: src/alu_core.vhd

Для ALU_OR результат равен побитовому ИЛИ двух операндов: y_v := a_i or b_i. Эта операция используется командой OR reg, adr.


Операция NOR

Файл: src/alu_core.vhd

Для ALU_NOR сначала выполняется OR, затем результат инвертируется: y_v := not (a_i or b_i). Эта операция используется командой NOR reg, adr.


Операция SRA

Файл: src/alu_core.vhd

SRA выполняет арифметический сдвиг вправо. Старший бит сохраняется, поэтому знак числа не меняется: y_v := a_i(15) & a_i(15 downto 1).

Младший вытесненный бит a_i(0) записывается во флаг C.


Операция INCS

Файл: src/alu_core.vhd

INCS увеличивает операнд на единицу только тогда, когда входной флаг S равен '1'. Если flag_s_i = '0', значение остается прежним.

Для контроля переноса используется 17-битная переменная sum17. Флаг C берется из старшего, 17-го бита суммы.


Формирование флагов АЛУ

Файл: src/alu_core.vhd

Флаг Z устанавливается, если результат равен 0000h. Флаг S равен старшему биту результата y_v(15). Флаг C формируется операциями SRA и INCS. Флаг O в данной реализации учитывается для INCS.


Регистр флагов

Файл: src/flags_reg.vhd

flags_reg хранит четыре флага: Z, S, C и O. При сбросе все флаги очищаются. При we_i = '1' в регистр записываются значения z_i, s_i, c_i и o_i.

Выходы z_o, s_o, c_o и o_o постоянно отражают текущее сохраненное состояние флагов.


Регистровый файл без отладки

Файл: src/reg_file12x16.vhd

Модуль реализует 12 регистров по 16 бит. Внутренний массив regs хранит значения регистров.

Чтение выполняется асинхронно через функцию read_reg. Если индекс меньше REG_COUNT, возвращается выбранный регистр; если индекс вне диапазона, возвращается нулевое слово.

Запись выполняется синхронно по фронту clk_i при we_i = '1'.


Регистровый файл с отладочными выходами

Файл: src/reg_file12x16_dbg.vhd

Этот модуль повторяет логику обычного регистрового файла, но дополнительно выводит r0_o...r11_o. Эти выходы нужны для наблюдения содержимого регистров на временных диаграммах и в полной системной проверке.

В cpu_core используется именно debug-версия, чтобы можно было проверять значения R1...R7 после выполнения программы.


Стек 7 x 16

Файл: src/stack7x16.vhd

Стек хранит 7 слов по 16 бит. Внутренний массив mem содержит данные, а sp_r хранит указатель вершины.

Пустой стек имеет sp_r = STACK_DEPTH, то есть 7. При PUSH указатель уменьшается, а слово записывается в mem(sp_i - 1). При POP слово читается из mem(sp_i), а указатель увеличивается.


Признаки пустого и полного стека

Файл: src/stack7x16.vhd

empty_o устанавливается, когда sp_r = 7. full_o устанавливается, когда sp_r = 0.

Перед PUSH проверяется, что sp_i > 0, чтобы не выйти за нижнюю границу стека. Перед POP проверяется, что sp_i < STACK_DEPTH, чтобы не читать из пустого стека.


Синхронное ПЗУ команд

Файл: src/rom_sync.vhd

rom_sync моделирует синхронное ПЗУ. При en_i = '1' по фронту clk_i из массива ROM_INIT выбирается слово с адресом addr_i(7 downto 0), и результат записывается в q_r.

Выход data_o подключен к q_r, поэтому данные появляются синхронно после тактового фронта.


Синхронное ОЗУ данных

Файл: src/ram_sync.vhd

ram_sync моделирует синхронную память данных. При en_i = '1' вычисляется индекс по младшим 8 битам адреса.

Если we_i = '1', в память записывается din_i. Независимо от записи на выход q_r помещается текущее содержимое выбранной ячейки.


Начальный образ ROM

Файл: src/program_image_pkg.vhd

Пакет содержит константу ROM_INIT с демонстрационной программой. В программе используются команды MOV, SRA, INCS, PUSH, OR, NOR, POP, JZ, JMP и HLT.

Команды записаны в двухсловном формате: по четному адресу лежит opcode с номером регистра, по следующему адресу - операнд или адрес перехода.


Начальный образ RAM

Файл: src/data_image_pkg.vhd

Пакет содержит константу RAM_INIT с исходными данными для программы. Например, по адресам 0020h...0025h размещены значения, которые затем читаются командами MOV, OR и NOR.

Адреса 000Ah...000Ch зарезервированы для записи трех слов DMA.


Кэш данных 4-way

Файл: src/cache_4way_age.vhd

cache_4way_age является рабочей моделью кэша данных. Кэш имеет 16 множеств и 4 направления. Для каждой строки хранятся данные, тег, valid-бит и 2-битный возраст.

Младшие 4 бита адреса addr(3 downto 0) выбирают множество. Старшие 12 бит addr(15 downto 4) являются тегом.


Состояния кэша

Файл: src/cache_4way_age.vhd

Автомат кэша имеет состояния IDLE, WAIT_READ_GRANT, WAIT_READ_DATA и WAIT_WRITE_GRANT.

IDLE обрабатывает запрос CPU и определяет hit/miss. WAIT_READ_GRANT ожидает доступ к RAM при промахе чтения. WAIT_READ_DATA принимает данные из RAM и заполняет строку. WAIT_WRITE_GRANT выполняет сквозную запись в RAM.


Проверка попадания в кэш

Файл: src/cache_4way_age.vhd

При запросе CPU кэш просматривает все четыре направления выбранного множества. Попадание фиксируется, если valid_r(set, way) = '1' и tag_r(set, way) совпадает с тегом адреса.

При hit на чтение данные сразу возвращаются процессору, cpu_ready_o устанавливается в '1', а hit_o показывает успешное попадание.


Выбор строки для замещения

Файл: src/cache_4way_age.vhd

Если среди четырех направлений есть невалидная строка, для заполнения выбирается она. Если все строки валидны, выбирается строка с наибольшим значением age_r.

Так реализовано требуемое замещение по наибольшей давности хранения.


Промах чтения кэша

Файл: src/cache_4way_age.vhd

При miss на чтение кэш выставляет ram_req_o = '1', ram_we_o = '0' и передает в RAM адрес запроса. После получения grant автомат переходит к ожиданию данных.

Когда данные приходят из RAM, они записываются в выбранную строку кэша, тег и valid-бит обновляются, а процессору возвращается считанное слово.


Обновление возраста строк кэша

Файл: src/cache_4way_age.vhd

После заполнения новой строки ее возраст сбрасывается в 0. Возраст остальных валидных строк выбранного множества увеличивается через inc_age.

Функция inc_age работает с насыщением: значение "11" дальше не увеличивается.


Сквозная запись кэша

Файл: src/cache_4way_age.vhd

При записи CPU кэш всегда отправляет данные в RAM, то есть использует write-through. Если адрес уже есть в кэше, строка дополнительно обновляется внутри data_r.

Если записи по адресу в кэше нет, данные после получения доступа к RAM могут быть помещены в выбранную строку кэша.


Структурная модель кэша для схемы

Файл: src/cache_4way_structural_doc.vhd

Этот файл сделан для документации и RTL Viewer. Он раскладывает кэш на отдельные простые подблоки: память данных, память тегов, valid-биты, счетчики возраста, компараторы тегов, логику hit/miss, мультиплексор данных, выбор жертвы и автомат управления.

В system_core используется не этот файл, а рабочий cache_4way_age. Структурная версия нужна, чтобы схема кэша была понятной и подписанной.


Память данных направления кэша

Файл: src/cache_4way_structural_doc.vhd

cache_data_way_doc хранит данные одного направления для всех 16 множеств. При we_i = '1' слово data_i записывается в ячейку выбранного множества set_i.

Таких блоков в структурной модели четыре - по одному на каждое направление кэша.


Память тегов направления кэша

Файл: src/cache_4way_structural_doc.vhd

cache_tag_way_doc хранит 12-битные теги строк. При записи в строку кэша вместе с данными записывается тег адреса, чтобы в дальнейшем можно было определить попадание.


Valid-бит строки кэша

Файл: src/cache_4way_structural_doc.vhd

cache_valid_way_doc хранит признак действительности строки. При сбросе все valid-биты очищаются, потому что содержимое кэша после reset считается недействительным.


Счетчик возраста строки кэша

Файл: src/cache_4way_structural_doc.vhd

cache_age_way_doc хранит 2-битный возраст строки. При записи новой строки возраст сбрасывается, а при inc_i = '1' увеличивается с насыщением.

Этот счетчик используется для выбора наиболее старой строки при замещении.


Сравнение тегов

Файл: src/cache_4way_structural_doc.vhd

cache_tag_compare_doc сравнивает тег запроса с тегом конкретного направления. Если теги равны, equal_o становится '1'.

Сам по себе equal_o еще не означает hit, потому что строка также должна быть валидной.


Логика hit/miss кэша

Файл: src/cache_4way_structural_doc.vhd

cache_hit_miss_logic_doc объединяет результаты сравнения тегов и valid-биты. Для каждого направления формируется way_hit = tag_equal and valid.

Общий hit равен OR от всех way_hit. miss является инверсией hit.


Мультиплексор данных кэша

Файл: src/cache_4way_structural_doc.vhd

cache_hit_mux_doc выбирает данные того направления, в котором произошло попадание. Одновременно формируется номер hit_way_o, который нужен управляющей логике.


Выбор жертвы в структурном кэше

Файл: src/cache_4way_structural_doc.vhd

cache_victim_select_doc сначала ищет невалидное направление. Если все направления валидны, выбирается направление с максимальным возрастом.

На выходе формируются victim_o в двоичном виде и onehot_o для управления записью конкретного направления.


Автомат управления структурным кэшем

Файл: src/cache_4way_structural_doc.vhd

cache_control_doc определяет, когда кэш готов ответить CPU, когда нужно запросить RAM, когда нужно записать строку и какие направления должны обновляться.

Состояния автомата отражают основные ситуации: чтение с попаданием, чтение с промахом, заполнение после промаха и сквозная запись.


DMA-контроллер

Файл: src/dma_controller_3word.vhd

DMA-контроллер записывает три 16-битных слова внешнего устройства в RAM. Базовый адрес задается generic BASE_ADDR_G и по умолчанию равен 000Ah.

Вход start_i запускает передачу. Вход dev_valid_i показывает, что dev_data_i содержит достоверное слово.


Автомат DMA

Файл: src/dma_controller_3word.vhd

Автомат DMA имеет состояния IDLE, REQ_BUS, WRITE_WORD и FINISH.

В IDLE контроллер ожидает start_i. В REQ_BUS запрашивает шину. В WRITE_WORD при наличии grant_i и dev_valid_i формирует запись в RAM и увеличивает index_r. После трех слов переходит в FINISH и выставляет done_o.


Адресация DMA

Файл: src/dma_controller_3word.vhd

Адрес записи формируется как BASE_ADDR_G + index_r. Так три слова попадают по адресам 000Ah, 000Bh и 000Ch.

Счетчик index_r имеет 2 бита, потому что требуется передать только три слова.


Арбитр шины

Файл: src/bus_arbiter_2master.vhd

Арбитр распределяет доступ к RAM между двумя мастерами: CPU через кэш и DMA.

DMA имеет приоритет: grant_dma_o равен req_dma_i. CPU получает grant_cpu_o только тогда, когда есть req_cpu_i и нет запроса DMA.


Предсказатель переходов A4

Файл: src/branch_predictor.vhd

Предсказатель состоит из таблицы PHT на 16 двухбитных счетчиков, BTB с адресами целей переходов, valid-битов BTB и регистра глобальной истории ghr_r.

Индекс таблиц формируется как PC(1 downto 0) || GHR(1 downto 0), что соответствует варианту A4.


Выдача прогноза перехода

Файл: src/branch_predictor.vhd

При query_valid_i = '1' вычисляется индекс по текущему PC и истории GHR. Если старший бит счетчика PHT равен '1' и запись BTB валидна, предсказатель выдает pred_taken_o = '1' и адрес pred_target_o.

Если счетчик не указывает на переход или BTB невалиден, прогноз считается "не переходить".


Обновление предсказателя

Файл: src/branch_predictor.vhd

После фактического выполнения условного перехода CPU подает update_valid_i. Если переход был выполнен, счетчик PHT увеличивается с насыщением, в BTB записывается целевой адрес и устанавливается valid-бит.

Если переход не был выполнен, счетчик PHT уменьшается. Регистр GHR сдвигается и запоминает новый исход перехода.


Тест АЛУ

Файл: tb/tb_alu_core.vhd

Тестбенч проверяет отдельный модуль alu_core. Он подает операнды и коды операций для SRA, INCS, OR и NOR, затем через assert сравнивает результат с ожидаемым.

Например, SRA для 8001h должен дать C000h и установить C = 1, S = 1.


Тест стека

Файл: tb/tb_stack7x16.vhd

Тестбенч проверяет stack7x16. После сброса стек должен быть пустым и иметь SP = 7. Затем выполняется несколько PUSH и POP.

Проверяется принцип LIFO: первым извлекается последнее записанное значение. После всех POP стек снова должен стать пустым.


Тест DMA и RAM

Файл: tb/tb_mem_dma.vhd

Тестбенч соединяет dma_controller_3word с ram_sync. Арбитраж упрощен: dma_gnt напрямую равен dma_req.

Во время записи monitor проверяет, что три слова записываются именно по адресам 000Ah, 000Bh и 000Ch со значениями 1111h, 2222h и 3333h.


Полный тест системы

Файл: tb/tb_system.vhd

Этот тестбенч запускает system_core, формирует reset, затем запускает DMA и передает три слова внешнего устройства. После появления halt = '1' проверяются итоговые значения регистров, флагов, указателя стека, признака завершения DMA и истории предсказателя.

Проверка подтверждает, что программа из ROM выполнилась правильно, стек вернулся в пустое состояние, DMA передал данные в RAM, а условный переход JZ был выполнен.


Итоговые проверки полной системы

Файл: tb/tb_system.vhd

В конце теста assert проверяет ожидаемые значения: R1 = C001h после SRA и INCS, R2 = F000h после OR и NOR, R3 = C001h после POP, R4 = 0000h после NOR, R5 и R6 остаются нулевыми из-за переходов, R7 считывает первое слово DMA из RAM[000Ah].

Также проверяются финальные флаги Z,S,C,O = 1000, пустой стек SP = 7, завершение DMA и история предсказателя bp_hist = 01.
