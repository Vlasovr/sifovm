# Блок общих операций: текст и что снимать

Нумерацию рисунков и подразделов замени под свою пояснительную записку. Если раздел 2.4 уже занят кэшем, этот пункт называй следующим свободным номером.

## Что важно

В проекте нет отдельной команды `NOP`, как у преподавателя. Поэтому подраздел "Блок операции NOP" не нужен. В твоем проекте неиспользуемые коды операций переводят процессор в `S_HALT`, а штатная команда останова называется `HLT`.

Блок общих операций в твоем проекте - это не отдельный BDF-блок, а автомат и исполнительная часть `cpu_core`. Он включает:

- выборку первого слова команды `IR0`;
- выборку второго слова команды `IR1`;
- декодирование кода операции;
- обращение к кэшу данных;
- запись/чтение регистров общего назначения;
- работу АЛУ и регистра флагов;
- работу стека;
- переходы `JMP` и `JZ`;
- останов `HLT`.

## Готовый текст для вставки

### Блок общих операций

Блок общих операций предназначен для выполнения общего цикла работы процессорного ядра и формирования управляющих воздействий для исполнительных устройств микро-ЭВМ. В проекте данный блок реализован в составе сущности `cpu_core` и включает автомат управления, регистры команд `IR0` и `IR1`, счетчик команд `PC`, интерфейс к ПЗУ команд, интерфейс к кэш-памяти данных, регистровый файл, АЛУ, регистр флагов и стек.

В отличие от варианта, приведенного в образце, в данной микро-ЭВМ отсутствует отдельная команда `NOP`. Неиспользуемые коды операций считаются зарезервированными и переводят процессор в безопасное состояние останова. Штатная остановка выполнения программы выполняется командой `HLT`.

Работа процессора основана на фиксированном двухсловном формате команды. Первое слово команды записывается в регистр `IR0` и содержит код операции и номер регистра общего назначения. Второе слово записывается в регистр `IR1` и используется как адрес операнда в ОЗУ данных, адрес перехода в ПЗУ команд или резервное поле для команд, которым адрес не требуется.

Общий цикл выполнения команды начинается с выборки первого слова команды из ПЗУ. Для этого в состоянии `S_FETCH0_REQ` на адресный вход ПЗУ выдается значение `PC`, затем в состояниях `S_FETCH0_WAIT` и `S_FETCH0_LATCH` слово команды принимается и записывается в `IR0`. После этого выполняется выборка второго слова команды: адрес ПЗУ увеличивается на единицу, а считанное слово записывается в `IR1`. Далее автомат переходит в состояние `S_DECODE`, где анализируется поле `OPCODE`.

После декодирования выбирается один из исполнительных маршрутов. Команды чтения из памяти `MOV adr, Rn`, `OR Rn, adr` и `NOR Rn, adr` переводят автомат в состояние `S_CACHE_READ`. Команда записи `MOV Rn, adr` переводит автомат в состояние `S_CACHE_WRITE`. Команды `SRA` и `INCS` выполняются через АЛУ, команды `PUSH` и `POP` используют стек, а команды `JMP` и `JZ` изменяют значение счетчика команд `PC`.

### Общий цикл выборки и декодирования

Выборка команды выполняется одинаково для всех операций. Сначала из ПЗУ считывается слово `IR0`, затем слово `IR1`. Благодаря фиксированному формату команда всегда занимает два 16-разрядных слова, поэтому после завершения обычной операции значение `PC` увеличивается на два. Исключением являются команды передачи управления, при которых в `PC` загружается адрес из `IR1`.

В состоянии `S_DECODE` поле `IR0(15..8)` сравнивается с кодами операций. Поле `IR0(7..4)` используется как номер регистра общего назначения. Для команд обмена с памятью и арифметико-логических команд поле `IR1` задает адрес операнда в памяти данных. Для команд `JMP` и `JZ` поле `IR1` задает адрес перехода в ПЗУ команд.

### Операция HLT

Команда `HLT` предназначена для останова выполнения программы. При декодировании кода операции `00h` автомат управления переходит в состояние `S_HALT`. В этом состоянии выходной сигнал `halt_o` устанавливается в единицу, а автомат остается в состоянии останова до сброса микро-ЭВМ. Такой режим используется для завершения тестовой программы и фиксации результатов моделирования.

### Операция M->R

Операция `MOV adr, Rn` выполняет чтение слова из памяти данных и запись результата в регистр общего назначения. После декодирования команды автомат переходит в состояние `S_CACHE_READ`. На вход кэш-памяти передается адрес из `IR1`, а сигнал записи `cache_we_o` остается равным нулю. После завершения обращения к кэшу и появления сигнала `cache_ready_i` считанное слово поступает на вход регистрового файла и записывается в регистр `Rn` в состоянии `S_RF_WRITE_MEM`.

Если требуемое слово уже находится в кэш-памяти, формируется сигнал попадания `cache_hit_i`, и обращение к ОЗУ не выполняется. При промахе кэш-память запрашивает слово из ОЗУ, заполняет выбранную строку и затем выдает данные процессору.

### Операция R->M

Операция `MOV Rn, adr` выполняет запись слова из регистра общего назначения в память данных. После декодирования команды автомат переходит в состояние `S_CACHE_WRITE`. На адресный вход кэша передается `IR1`, а на вход данных - содержимое выбранного регистра `Rn`. Сигнал `cache_we_o` устанавливается в единицу. После завершения записи и появления `cache_ready_i` автомат переходит к завершению команды.

Так как кэш-память работает в режиме сквозной записи, при выполнении операции записи данные передаются не только в строку кэша, но и в ОЗУ. Это подтверждается активностью сигналов записи памяти на временной диаграмме.

### Арифметико-логические операции

Арифметико-логические команды выполняются блоком `U_ALU`. Для команд `OR` и `NOR` сначала выполняется чтение второго операнда из памяти через кэш, после чего значение регистра `Rn` и считанное слово поступают на входы АЛУ. Команда `OR` формирует побитовое ИЛИ двух операндов, а команда `NOR` формирует инверсию результата побитового ИЛИ.

Команды `SRA` и `INCS` используют только значение регистра `Rn`. Для `SRA` выполняется арифметический сдвиг вправо с сохранением знакового разряда. Для `INCS` выполняется инкремент регистра на значение флага `S`. Результат работы АЛУ записывается обратно в выбранный регистр в состоянии `S_ALU_WRITE`. Одновременно обновляются флаги `Z`, `S`, `C` и `O`.

### Стековые операции

Команда `PUSH Rn` записывает значение регистра `Rn` в стек. При декодировании данной команды автомат переходит в состояние `S_STACK_PUSH`, где формируется сигнал `stack_push`. Указатель стека уменьшается, а значение регистра помещается в стековую память.

Команда `POP Rn` извлекает слово из стека. Сначала в состоянии `S_STACK_POP` формируется сигнал чтения из стека, после чего считанное слово записывается в регистр `Rn` в состоянии `S_RF_WRITE_POP`. Значение указателя стека при этом увеличивается. Для контроля работы стекового блока на временной диаграмме используется сигнал `DBG_SP`.

### Команды передачи управления

Команда `JMP adr` выполняет безусловную загрузку адреса из `IR1` в счетчик команд `PC`. После выполнения перехода следующая выборка команды начинается уже с нового адреса.

Команда `JZ adr` выполняет условный переход по флагу `Z`. Если флаг `Z` установлен, в `PC` загружается адрес из `IR1`. Если флаг `Z` сброшен, выполнение продолжается со следующей команды, и значение `PC` увеличивается на два. Команда `JZ` также используется для проверки работы предсказателя переходов, поскольку результат перехода зависит от флагов АЛУ.

### Завершение операции

Большинство команд после выполнения переходят в состояние `S_FINISH`. В этом состоянии значение `PC` увеличивается на два, после чего автомат возвращается к выборке следующей команды. Для команд `JMP` и `JZ` значение `PC` изменяется непосредственно в состоянии выполнения перехода, поэтому они возвращают автомат к выборке команды без промежуточного увеличения адреса на два.

Таким образом, блок общих операций обеспечивает единый цикл выборки, декодирования и выполнения команд микро-ЭВМ. Регулярный двухсловный формат команды упрощает автомат управления, а разделение исполнительных маршрутов позволяет использовать одни и те же функциональные блоки для нескольких команд: кэш-память для обмена с ОЗУ, АЛУ для логических и арифметических операций, регистровый файл для хранения операндов, стек для команд `PUSH` и `POP`, а счетчик команд `PC` для передачи управления.
