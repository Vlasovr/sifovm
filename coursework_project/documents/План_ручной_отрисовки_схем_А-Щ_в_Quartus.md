# План ручной отрисовки схем приложений А-Щ в Quartus

Документ сделан под текущую пояснительную записку `Пояснительная_записка.docx` и фактические VHDL-файлы проекта. Цель - не получить автоматически сгенерированный RTL на 90 страниц, а вручную начертить аккуратные структурные схемы для печати, похожие по стилю на схему кэша одногруппника: белое поле, мелкие функциональные блоки, шины, компараторы, регистры, мультиплексоры, дешифраторы и управляющие связи.

## 0. Что обязательно соблюдать во всех схемах

1. Не писать на схемах `VHDL`, `RTL Viewer`, `test program`, `образец преподавателя`, `как у преподавателя`, `как у товарища`. На листах должны быть только технические названия блоков и сигналов.
2. Все схемы делать под твой вариант:
   - разрядность данных: `16 бит`;
   - разрядность адреса: `16 бит`;
   - РОН: `R0...R11`, всего `12` регистров;
   - стек: `7 x 16`, ячейки `STACK0...STACK6`;
   - операции: `HLT`, `M->R`, `R->M`, `OR`, `NOR`, `SRA`, `INCS`, `PUSH`, `POP`, `JMP`, `JZ`;
   - АЛУ: `OR`, `NOR`, `SRA`, `INCS`;
   - кэш: `4-way`, `16 sets`, `TAG = A[15..4]`, `SET = A[3..0]`, `DATA 16 bit`, `VALID`, `AGE[1..0]`;
   - КПДП: запись `3` слов, база `000Ah`;
   - предсказатель переходов: индекс `PC[1..0] || GHR[1..0]`, `PHT`, `BTB`, `GHR`.
3. В каждой схеме справа внизу подписывать:
   - `ПРИЛОЖЕНИЕ <буква>`;
   - полное название приложения из ПЗ;
   - `Разраб. Власов Р.Е.`;
   - `Пров. Третьяков`.
4. Не перегружать лист всеми битами. Для 16 одинаковых разрядов можно рисовать 4-8 повторяющихся элементов и подписывать `x16` или `[15..0]`. Это нормально для структурной схемы.
5. Везде использовать единый стиль:
   - входы слева, выходы справа;
   - управляющие сигналы сверху или снизу;
   - память и регистры прямоугольниками;
   - мультиплексоры треугольником или блоком `MUX`;
   - дешифраторы блоком `DECODER`;
   - компараторы блоком `CMP`;
   - логика `AND/OR/NOT` отдельными вентилями;
   - шины подписывать над линией: `data[15..0]`, `addr[15..0]`, `tag[11..0]`, `set[3..0]`.
6. Если рисуешь в BDF, лучше не пытаться всё компилировать. Это графическая часть. Главное - технически корректная структура и подписи.

## 1. Как создать рабочий проект для ручных схем в Quartus

1. Открой `Quartus II`.
2. Выбери `File -> New Project Wizard`.
3. В поле рабочей папки укажи:
   `D:\git\sifovm\coursework_project\quartus_manual_schemes`
4. Имя проекта:
   `manual_appendix_schemes`
5. Top-level entity можно указать любое, например:
   `manual_appendix_schemes`
6. На шаге добавления файлов ничего не добавляй.
7. На шаге выбора устройства выбери:
   - Family: `Cyclone II`;
   - Device: можно `AUTO` или любой доступный Cyclone II, если Quartus просит конкретный.
8. Нажми `Finish`.

## 2. Как создавать каждый лист

Для каждого приложения делай отдельный `.bdf`:

1. `File -> New`.
2. Выбери `Block Diagram/Schematic File`.
3. `File -> Save As`.
4. Сохраняй по шаблону:
   - `A_command_system.bdf`;
   - `B_memory.bdf`;
   - `V_control_unit.bdf`;
   - и так далее.
5. Включи сетку:
   - `View -> Show Grid`;
   - `View -> Snap to Grid`.
6. Для вставки блоков:
   - `Edit -> Insert Symbol`;
   - либо дважды щёлкнуть по пустому месту листа.
7. Для входов/выходов используй:
   - `primitives -> pin -> input`;
   - `primitives -> pin -> output`.
8. Для логики используй:
   - `primitives -> logic -> and2`;
   - `primitives -> logic -> or2`;
   - `primitives -> logic -> not`;
   - `primitives -> logic -> xor`;
   - если есть `and4/or4`, можно брать их.
9. Для регистров используй:
   - `primitives -> storage -> dff` или `dffe`;
   - если неудобно, рисуй прямоугольник с подписью `DFF REG[15..0]`.
10. Для сложных блоков можно рисовать прямоугольники вручную инструментами BDF и подписывать:
    - `lpm_decode`;
    - `lpm_mux`;
    - `lpm_compare`;
    - `lpm_add_sub`;
    - `RAM 16x16`;
    - `FSM`.
11. Для соединений:
    - обычные линии - `Orthogonal Node Tool`;
    - шины - `Bus Tool`;
    - имя шины ставь через `Node Name`, например `cpu_addr[15..0]`.
12. Чтобы схема выглядела как у одногруппников:
    - не делай большие цветные блоки;
    - делай много маленьких функциональных блоков;
    - оставляй много прямых линий-шин;
    - одинаковые блоки выравнивай столбцом;
    - не рисуй декоративные рамки вокруг каждого блока, только общий контур листа при необходимости.

## 2.1. Как в BDF быстро рисовать блоки, если нет нужного символа

В Quartus не обязательно искать идеальный готовый символ для каждого узла. Для печатной структурной схемы можно использовать прямоугольные блоки с техническими подписями.

1. Выбери инструмент прямоугольника/блока на панели BDF.
2. Нарисуй прямоугольник.
3. Двойной щелчок по тексту или `Text Tool`.
4. Впиши название, например:
   - `ADDR_SPLIT`;
   - `TAG WAY0`;
   - `DATA WAY0 16x16`;
   - `CMP TAG==REQ`;
   - `MUX 4->1`;
   - `FSM`.
5. Внутри блока второй строкой пиши краткую функцию:
   - `TAG=A[15..4]`;
   - `SET=A[3..0]`;
   - `valid & tag_eq`;
   - `victim=max AGE`.
6. Если блок повторяется, выдели его рамкой мышью и нажми `Ctrl+C`, затем `Ctrl+V`.
7. После вставки меняй только номер:
   - `WAY0 -> WAY1`;
   - `CMP0 -> CMP1`;
   - `STACK0 -> STACK1`.

Так схема выглядит ближе к RTL/структурному виду, чем если пытаться поставить один огромный самодельный блок.

## 2.2. Как подписывать шины и линии

1. Обычную линию веди инструментом `Orthogonal Node Tool`.
2. Для шины используй `Bus Tool`.
3. После проведения линии выбери `Node Name Tool`.
4. Кликни по линии.
5. Введи имя:
   - `addr[15..0]`;
   - `data[15..0]`;
   - `tag[11..0]`;
   - `set[3..0]`;
   - `hit[3..0]`;
   - `age[1..0]`.
6. Если линия управляющая, без диапазона:
   - `we`;
   - `req`;
   - `grant`;
   - `ready`;
   - `hit`;
   - `miss`.
7. Шины данных лучше рисовать толще/длиннее и подписывать один раз над линией.
8. Управляющие линии вести отдельно, чтобы они не сливались с шинами данных.

## 2.3. Как сделать шаблон листа

Сделай один пустой шаблон и потом копируй его:

1. Создай `template_appendix.bdf`.
2. Нарисуй тонкую рамку листа.
3. В правом нижнем углу поставь текст:
   - `ПРИЛОЖЕНИЕ __`;
   - `Схема комбинированная структурная ...`;
   - `Разраб. Власов Р.Е.`;
   - `Пров. Третьяков`.
4. Сохрани.
5. Для каждого нового приложения открывай шаблон и делай `File -> Save As`.

# ПРИЛОЖЕНИЕ А. Система команд микро-ЭВМ

## Что должно быть на листе

Это не схема устройства, а структурная схема формата и декодирования команд. Нужно показать, как из двух 16-битных слов получается код операции, номер регистра и адрес/операнд.

## Блоки

1. Слева входы:
   - `rom_data[15..0]`;
   - `pc[15..0]`;
   - `clk`;
   - `rst`.
2. Блок `PC register`.
3. Блок `ROM command memory`.
4. Два регистра команды:
   - `IR0[15..0]`;
   - `IR1[15..0]`.
5. Блок разбиения команды:
   - `OPCODE = IR0[15..8]`;
   - `RN = IR0[7..4]`;
   - `RES = IR0[3..0]`;
   - `ADDR/IMM = IR1[15..0]`.
6. Декодер `OPCODE DECODER 8->11`.
7. Справа выходы one-hot:
   - `op_hlt`;
   - `op_mr`;
   - `op_rm`;
   - `op_or`;
   - `op_nor`;
   - `op_sra`;
   - `op_incs`;
   - `op_push`;
   - `op_pop`;
   - `op_jmp`;
   - `op_jz`.

## Как рисовать пошагово

1. Создай файл `A_command_system.bdf`.
2. Слева поставь вход `rom_data[15..0]`.
3. Ниже поставь входы `clk`, `rst`.
4. В верхней левой части поставь `PC register`.
5. От `PC register` проведи шину `rom_addr[15..0]` в блок `ROM command memory`.
6. От `ROM command memory` проведи шину `rom_data[15..0]` к двум регистрам:
   - верхний `IR0`;
   - нижний `IR1`.
7. Между ROM и регистрами подпиши управляющие сигналы:
   - `fetch0_latch` к `IR0`;
   - `fetch1_latch` к `IR1`.
8. Справа от `IR0` поставь блок `FIELD SPLIT`.
9. От `IR0` к `FIELD SPLIT` проведи шину `IR0[15..0]`.
10. Из `FIELD SPLIT` выведи:
    - `opcode[7..0]`;
    - `rn[3..0]`;
    - `reserved[3..0]`.
11. От `IR1` выведи шину `addr[15..0]`.
12. Справа поставь `OPCODE DECODER`.
13. От `opcode[7..0]` проведи шину в `OPCODE DECODER`.
14. Справа от декодера сделай 11 выходных линий, подписанных кодами команд.
15. Возле каждой линии подпиши код:
    - `00 HLT`;
    - `01 M->R`;
    - `02 R->M`;
    - `03 OR`;
    - `04 NOR`;
    - `05 SRA`;
    - `06 INCS`;
    - `07 PUSH`;
    - `08 POP`;
    - `09 JMP`;
    - `0A JZ`.

## Что не рисовать

1. Не рисовать `NOP`.
2. Не рисовать `ADDC`, `AND`, `NOT`, `ROL`, `CMP` - это не твой вариант.
3. Не писать тестовые значения программы на этом листе.

# ПРИЛОЖЕНИЕ Б. Совмещенный блок ЗУ

## Что должно быть на листе

Нужно показать, что у микро-ЭВМ есть отдельная память команд и память данных, а доступ к памяти данных идет через кэш и арбитр CPU/DMA.

## Блоки

1. `CPU core`.
2. `ROM command memory 256x16`.
3. `Cache 4-way`.
4. `RAM data memory 256x16`.
5. `DMA controller 3 words`.
6. `CPU/DMA arbiter`.
7. Мультиплексоры выбора:
   - `ram_addr mux`;
   - `ram_wdata mux`;
   - `ram_we mux`.

## Как рисовать пошагово

1. Создай файл `B_memory.bdf`.
2. Слева поставь блок `CPU core`.
3. Сверху справа от CPU поставь `ROM command memory 256x16`.
4. Проведи от CPU к ROM:
   - `rom_addr[15..0]`;
   - `rom_en`.
5. Проведи от ROM к CPU:
   - `rom_data[15..0]`.
6. В центре поставь блок `Cache 4-way data cache`.
7. Проведи от CPU к cache:
   - `cache_req`;
   - `cache_we`;
   - `cache_addr[15..0]`;
   - `cache_wdata[15..0]`.
8. Проведи от cache к CPU:
   - `cache_rdata[15..0]`;
   - `cache_ready`;
   - `cache_hit`;
   - `cache_miss`.
9. Справа поставь `RAM data memory 256x16`.
10. Между cache и RAM поставь `CPU/DMA arbiter`.
11. Снизу поставь `DMA controller 3 words @000A`.
12. От cache к арбитру проведи `req_cpu`.
13. От DMA к арбитру проведи `req_dma`.
14. От арбитра к cache проведи `grant_cpu`.
15. От арбитра к DMA проведи `grant_dma`.
16. Перед RAM поставь три mux:
    - адрес: `cache_ram_addr` или `dma_addr`;
    - данные: `cache_ram_wdata` или `dma_wdata`;
    - запись: `cache_ram_we` или `dma_we`.
17. От mux к RAM проведи:
    - `ram_addr[15..0]`;
    - `ram_din[15..0]`;
    - `ram_we`;
    - `ram_en`.
18. От RAM обратно к cache проведи `ram_rdata[15..0]`.

## Подписи

1. У ROM: `ПЗУ команд, 16-разрядное слово`.
2. У RAM: `ОЗУ данных, 16-разрядное слово`.
3. У cache: `4-way, 16 sets, TAG+VALID+AGE`.
4. У DMA: `3 words, BASE=000Ah`.

# ПРИЛОЖЕНИЕ В. Блок устройства управления

## Что должно быть на листе

Схема должна показывать автомат управления: выборка двух слов команды, декодирование, формирование управляющих сигналов для РОН, АЛУ, кэша, стека, PC, HLT и предсказателя переходов.

## Блоки

1. `STATE REGISTER`.
2. `NEXT STATE LOGIC`.
3. `OPCODE DECODER`.
4. `CONTROL MATRIX`.
5. `PC CONTROL`.
6. `FETCH CONTROL`.
7. `CACHE CONTROL OUT`.
8. `ALU CONTROL OUT`.
9. `RF CONTROL OUT`.
10. `STACK CONTROL OUT`.
11. `BRANCH/BP CONTROL OUT`.
12. `HALT LOGIC`.

## Как рисовать пошагово

1. Создай файл `V_control_unit.bdf`.
2. Слева поставь входы:
   - `clk`;
   - `rst`;
   - `ir0[15..0]`;
   - `ir1[15..0]`;
   - `flags[3..0]`;
   - `cache_ready`;
   - `bp_pred`;
   - `bp_target[15..0]`.
3. В центре слева поставь `STATE REGISTER`.
4. Рядом поставь блок `NEXT STATE LOGIC`.
5. Сделай обратную связь:
   - `state[4..0]` из регистра в `NEXT STATE LOGIC`;
   - `next_state[4..0]` из логики обратно в регистр.
6. От `ir0[15..8]` проведи шину в `OPCODE DECODER`.
7. Из `OPCODE DECODER` выведи 11 линий операций.
8. Эти линии заведи в `CONTROL MATRIX`.
9. В `CONTROL MATRIX` также заведи:
   - `state[4..0]`;
   - `flags[3..0]`;
   - `cache_ready`.
10. Справа от `CONTROL MATRIX` выведи группы сигналов:
    - `rom_en`, `rom_addr_sel`;
    - `ir0_we`, `ir1_we`;
    - `rf_we`, `rf_wr_addr[3..0]`;
    - `alu_op[2..0]`;
    - `flag_we`;
    - `cache_req`, `cache_we`;
    - `stack_push`, `stack_pop`;
    - `pc_load`, `pc_next_sel`;
    - `bp_query`, `bp_update`;
    - `halt`.
11. Отдельно нарисуй маленький блок `HLT LOGIC`:
    - вход `op_hlt`;
    - выход `halt`.
12. Отдельно нарисуй блок `BRANCH CONTROL`:
    - входы `op_jmp`, `op_jz`, `Z flag`, `ir1[15..0]`;
    - выход `pc_load`;
    - выход `pc_next = ir1`.

## Проверка

На схеме должны быть состояния `S_FETCH0`, `S_FETCH1`, `S_DECODE`, `S_CACHE_READ`, `S_CACHE_WRITE`, `S_ALU_WRITE`, `S_STACK_PUSH`, `S_STACK_POP`, `S_BRANCH_JMP`, `S_BRANCH_JZ`, `S_HALT`. Можно не писать все в одном блоке, но основные обязательно.

# ПРИЛОЖЕНИЕ Г. Блок специальных регистров

## Что должно быть на листе

Покажи регистры, которые не являются РОН: PC, IR0, IR1, FR, SP, GHR/служебные регистры предсказателя, регистр состояния автомата.

## Блоки

1. `PC[15..0]`.
2. `IR0[15..0]`.
3. `IR1[15..0]`.
4. `FR[3..0] = Z,S,C,O`.
5. `SP[2..0]`.
6. `STATE[4..0]`.
7. `GHR[1..0]`.
8. Мультиплексор `PC_NEXT MUX`.

## Как рисовать пошагово

1. Создай файл `G_special_registers.bdf`.
2. Слева поставь входы:
   - `clk`;
   - `rst`;
   - `rom_data[15..0]`;
   - `alu_flags[3..0]`;
   - `stack_sp_next[2..0]`;
   - `branch_target[15..0]`;
   - `bp_hist_next[1..0]`.
3. В центре сверху поставь `PC register`.
4. Перед PC поставь `PC_NEXT MUX`.
5. Входы mux:
   - `PC + 2`;
   - `IR1 branch target`;
   - при желании `reset vector 0000h`.
6. Ниже поставь `IR0 register`.
7. Ниже поставь `IR1 register`.
8. От `rom_data[15..0]` проведи шину к `IR0` и `IR1`.
9. Подпиши управляющие входы:
   - `ir0_we`;
   - `ir1_we`.
10. Справа от `IR0` выведи:
    - `opcode[7..0]`;
    - `rn[3..0]`.
11. Справа от `IR1` выведи:
    - `addr/target[15..0]`.
12. В нижней части поставь `FR flags register`.
13. Внутри подпиши `Z S C O`.
14. Рядом поставь `SP register/counter`.
15. Подпиши:
    - `empty when SP=7`;
    - `full when SP=0`.
16. Справа поставь `STATE register`.
17. Для предсказателя добавь маленький `GHR[1..0]`.

## Что важно

FR лучше рисовать как 4 триггера или один регистр `[3..0]`, но подпиши порядок флагов. В debug-выводе проекта флаги идут как `Z&S&C&O`.

# ПРИЛОЖЕНИЕ Д. Регистры общего назначения

## Что должно быть на листе

Блок РОН на 12 регистров по 16 бит с одним портом записи и двумя портами чтения.

## Блоки

1. `WRITE ADDRESS DECODER 4->12`.
2. `R0[15..0]` ... `R11[15..0]`.
3. `READ MUX A 12->1`.
4. `READ MUX B 12->1`.
5. Входы:
   - `clk`;
   - `rst`;
   - `we`;
   - `wr_addr[3..0]`;
   - `rd_addr_a[3..0]`;
   - `rd_addr_b[3..0]`;
   - `din[15..0]`.
6. Выходы:
   - `dout_a[15..0]`;
   - `dout_b[15..0]`.

## Как рисовать пошагово

1. Создай файл `D_register_file.bdf`.
2. Слева поставь вход `din[15..0]`.
3. Ниже поставь входы `wr_addr[3..0]`, `rd_addr_a[3..0]`, `rd_addr_b[3..0]`, `we`, `clk`, `rst`.
4. В центре слева поставь `DECODER 4->12`.
5. Входы decoder:
   - `wr_addr[3..0]`;
   - `we`.
6. Справа от decoder вертикально поставь 12 регистров:
   - `R0`;
   - `R1`;
   - ...
   - `R11`.
7. От `din[15..0]` проведи общую шину ко всем регистрам.
8. От decoder проведи линии `we0...we11` к каждому регистру.
9. Справа от регистров поставь два мультиплексора:
   - верхний `MUX_A 12->1`;
   - нижний `MUX_B 12->1`.
10. От каждого регистра проведи выход `q[15..0]` к обоим mux.
11. К `MUX_A` подведи `rd_addr_a[3..0]`.
12. К `MUX_B` подведи `rd_addr_b[3..0]`.
13. Справа выведи:
    - `dout_a[15..0]`;
    - `dout_b[15..0]`.

## Как сделать красиво

Регистры лучше поставить ровным столбцом. Если 12 не помещаются, делай два столбца по 6, но всё равно подписывай `R0...R11`.

# ПРИЛОЖЕНИЕ Е. Блок общих операций

## Что должно быть на листе

Это общий маршрут команд, которые не относятся к отдельной логике АЛУ: выборка, декодирование, HLT, JMP, M->R, R->M, связь с РОН, PC и кэшем.

## Блоки

1. `FETCH0/FETCH1`.
2. `IR0/IR1`.
3. `OPCODE DECODER`.
4. `HLT LOGIC`.
5. `JMP/JZ PC LOAD`.
6. `M->R cache read`.
7. `R->M cache write`.
8. `RF interface`.
9. `CACHE interface`.

## Как рисовать пошагово

1. Создай файл `E_common_operations.bdf`.
2. Слева поставь блок `FETCH UNIT`.
3. Внутри или рядом подпиши:
   - `S_FETCH0_REQ`;
   - `S_FETCH0_WAIT`;
   - `S_FETCH0_LATCH`;
   - `S_FETCH1_REQ`;
   - `S_FETCH1_WAIT`;
   - `S_FETCH1_LATCH`.
4. От `FETCH UNIT` проведи шины к `IR0` и `IR1`.
5. Справа от `IR0` поставь `OPCODE DECODER`.
6. Из декодера выведи линии:
   - `op_hlt`;
   - `op_jmp`;
   - `op_jz`;
   - `op_mr`;
   - `op_rm`.
7. Для HLT поставь отдельный блок:
   - вход `op_hlt`;
   - выход `halt_o`.
8. Для JMP/JZ поставь блок `PC LOAD LOGIC`.
9. В него заведи:
   - `op_jmp`;
   - `op_jz`;
   - `Z flag`;
   - `IR1[15..0]`.
10. Из него выведи:
    - `pc_load`;
    - `pc_next[15..0]`.
11. Для M->R поставь блок `CACHE READ`.
12. В него заведи:
    - `IR1[15..0] -> cache_addr`;
    - `cache_req=1`;
    - `cache_we=0`.
13. Из `CACHE READ` проведи:
    - `cache_rdata[15..0]` к `RF writeback`.
14. Для R->M поставь блок `CACHE WRITE`.
15. В него заведи:
    - `IR1[15..0] -> cache_addr`;
    - `RF_A[15..0] -> cache_wdata`;
    - `cache_req=1`;
    - `cache_we=1`.
16. Справа поставь `RF interface`.
17. В `RF interface` заведи:
    - `rn = IR0[7..4]`;
    - `rf_we`;
    - `rf_din[15..0]`.

## Что важно

Не рисуй `NOP`. В твоем проекте есть `HLT`, а неизвестные коды тоже уходят в останов.

# ПРИЛОЖЕНИЕ Ж. Операция безусловного перехода JMP

## Что должно быть на листе

Покажи, что `JMP adr` загружает в PC адрес из `IR1`.

## Блоки

1. `IR1 target register`.
2. `PC + 2`.
3. `NEXT PC MUX`.
4. `PC register`.
5. `JMP decode`.

## Как рисовать пошагово

1. Создай файл `ZH_jmp.bdf`.
2. Слева поставь вход `IR0[15..0]`.
3. Ниже поставь вход `IR1[15..0]`.
4. От `IR0[15..8]` проведи шину в маленький блок `CMP opcode = 09h`.
5. Выход компаратора подпиши `op_jmp`.
6. В центре поставь `NEXT PC MUX`.
7. На вход `0` mux заведи `PC + 2`.
8. На вход `1` mux заведи `IR1[15..0]`.
9. На вход выбора mux заведи `op_jmp`.
10. Справа поставь `PC register`.
11. От mux проведи `pc_next[15..0]` в `PC register`.
12. Из PC выведи `rom_addr[15..0]`.

## Подпись возле линии

`if opcode=09h then PC <= IR1`.

# ПРИЛОЖЕНИЕ И. Операция M->R

## Что должно быть на листе

Покажи чтение из памяти данных через кэш и запись результата в выбранный РОН.

## Блоки

1. `IR0 register`.
2. `IR1 address register`.
3. `opcode compare 01h`.
4. `CACHE READ`.
5. `RF writeback`.
6. `register address RN`.

## Как рисовать пошагово

1. Создай файл `I_m_to_r.bdf`.
2. Слева поставь `IR0[15..0]`.
3. Ниже поставь `IR1[15..0]`.
4. От `IR0[15..8]` проведи к блоку `CMP opcode = 01h`.
5. Выход подпиши `op_mr`.
6. От `IR0[7..4]` проведи линию `rn[3..0]` к `RF wr_addr`.
7. От `IR1[15..0]` проведи шину к `CACHE READ`.
8. В `CACHE READ` подпиши:
   - `cache_req = op_mr`;
   - `cache_we = 0`;
   - `cache_addr = IR1`.
9. От `CACHE READ` проведи выход:
   - `cache_rdata[15..0]`.
10. Справа поставь `RF WRITE PORT`.
11. В него заведи:
    - `wr_addr = rn`;
    - `din = cache_rdata`;
    - `we = cache_ready and op_mr`.
12. Справа выведи `R[n] <= RAM[IR1]`.

## Важная подпись

`M->R: RAM/cache data -> selected RON`.

# ПРИЛОЖЕНИЕ К. Операция R->M

## Что должно быть на листе

Покажи запись значения выбранного РОН в память данных через кэш с write-through в RAM.

## Блоки

1. `IR0 register`.
2. `IR1 address register`.
3. `opcode compare 02h`.
4. `RF read port A`.
5. `CACHE WRITE`.
6. `RAM write-through interface`.

## Как рисовать пошагово

1. Создай файл `K_r_to_m.bdf`.
2. Слева поставь `IR0[15..0]` и `IR1[15..0]`.
3. От `IR0[15..8]` проведи в `CMP opcode = 02h`.
4. Выход подпиши `op_rm`.
5. От `IR0[7..4]` проведи `rn[3..0]` к `RF read address`.
6. Поставь блок `RF READ PORT A`.
7. Из него выведи `rf_a[15..0]`.
8. В центре поставь `CACHE WRITE`.
9. В `CACHE WRITE` заведи:
   - `cache_req = op_rm`;
   - `cache_we = 1`;
   - `cache_addr = IR1`;
   - `cache_wdata = rf_a`.
10. Справа от cache поставь `RAM WRITE-THROUGH`.
11. От cache к RAM-интерфейсу проведи:
    - `ram_req`;
    - `ram_we`;
    - `ram_addr[15..0]`;
    - `ram_wdata[15..0]`.
12. Справа выведи `RAM[IR1] <= R[n]`.

## Важная подпись

`R->M: selected RON -> cache -> RAM`.

# ПРИЛОЖЕНИЕ Л. Арифметико-логическое устройство

## Что должно быть на листе

Общая структура АЛУ: входные регистры операндов, четыре операции, mux результата, блок флагов.

## Блоки

1. `A register`.
2. `B register`.
3. `ALU operation decoder`.
4. `OR block`.
5. `NOR block`.
6. `SRA block`.
7. `INCS block`.
8. `RESULT MUX 4->1`.
9. `FLAGS LOGIC`.
10. `RESULT register/writeback`.

## Как рисовать пошагово

1. Создай файл `L_alu.bdf`.
2. Слева поставь входы:
   - `A[15..0]`;
   - `B[15..0]`;
   - `flag_s`;
   - `alu_op[2..0]`.
3. После входов поставь два регистра:
   - `A_REG`;
   - `B_REG`.
4. Вверху поставь `ALU OP DECODER`.
5. Из него выведи линии:
   - `sel_or`;
   - `sel_nor`;
   - `sel_sra`;
   - `sel_incs`.
6. В центре вертикально поставь четыре блока:
   - `OR`;
   - `NOR`;
   - `SRA`;
   - `INCS`.
7. В `OR` заведи `A` и `B`.
8. В `NOR` заведи `A` и `B`.
9. В `SRA` заведи только `A`.
10. В `INCS` заведи `A` и `flag_s`.
11. Справа поставь `RESULT MUX 4->1`.
12. Входы mux:
    - `or_y`;
    - `nor_y`;
    - `sra_y`;
    - `incs_y`.
13. Выход mux подпиши `alu_y[15..0]`.
14. Справа снизу поставь `FLAGS LOGIC`.
15. В него заведи:
    - `alu_y[15..0]`;
    - `carry`;
    - `overflow`.
16. Из него выведи:
    - `Z`;
    - `S`;
    - `C`;
    - `O`.
17. Справа поставь `RF writeback`.

## Что важно

Коды операций АЛУ:
- `001 OR`;
- `010 NOR`;
- `011 SRA`;
- `100 INCS`.

# ПРИЛОЖЕНИЕ М. Операция OR

## Что должно быть на листе

Побитовое ИЛИ двух 16-битных операндов.

## Блоки

1. `A[15..0]`.
2. `B[15..0]`.
3. Набор вентилей `OR2 x16`.
4. `Y[15..0]`.
5. Маленький блок флагов `Z/S`.

## Как рисовать пошагово

1. Создай файл `M_or.bdf`.
2. Слева поставь вход `A[15..0]`.
3. Ниже поставь вход `B[15..0]`.
4. Сделай блок `BUS SPLIT A`.
5. Сделай блок `BUS SPLIT B`.
6. В центре поставь несколько вентилей `OR2`.
7. Если рисуешь не все 16, поставь 4 вентиля и подпиши группу `OR2 x16`.
8. Подпиши линии:
   - `A0/B0 -> Y0`;
   - `A1/B1 -> Y1`;
   - `...`;
   - `A15/B15 -> Y15`.
9. Справа поставь `BUS JOIN`.
10. От него выведи `Y[15..0]`.
11. Ниже поставь `ZERO/SIGN FLAGS`.
12. Проведи `Y[15..0]` к блоку флагов.

## Формула на схеме

`Y = A OR B`.

# ПРИЛОЖЕНИЕ Н. Операция NOR

## Что должно быть на листе

Побитовое ИЛИ-НЕ: сначала OR, затем инверсия результата.

## Блоки

1. `A[15..0]`.
2. `B[15..0]`.
3. `OR2 x16`.
4. `NOT x16`.
5. `Y[15..0]`.
6. `ZERO/SIGN FLAGS`.

## Как рисовать пошагово

1. Создай файл `N_nor.bdf`.
2. Слева поставь `A[15..0]` и `B[15..0]`.
3. В центре слева поставь группу `OR2 x16`.
4. Справа от неё поставь группу `NOT x16`.
5. От `A` и `B` проведи шины к OR.
6. От OR проведи промежуточную шину `or_y[15..0]` к NOT.
7. От NOT выведи `Y[15..0]`.
8. Подключи `Y[15..0]` к блоку `FLAGS`.

## Формула на схеме

`Y = NOT (A OR B)`.

# ПРИЛОЖЕНИЕ П. Операция SRA

## Что должно быть на листе

Арифметический сдвиг вправо с сохранением знакового бита.

## Блоки

1. `A[15..0]`.
2. `BUS SPLIT`.
3. `SIGN EXTEND`.
4. `SHIFT WIRING`.
5. `C flag = A[0]`.
6. `Y[15..0]`.

## Как рисовать пошагово

1. Создай файл `P_sra.bdf`.
2. Слева поставь вход `A[15..0]`.
3. В центре поставь `BUS SPLIT`.
4. Из него выведи:
   - `A[15]`;
   - `A[15..1]`;
   - `A[0]`.

`Y[14..0] = A[15..1]`

`C = A[0]`

# ПРИЛОЖЕНИЕ Р. Операция INCS

## Что должно быть на листе

Инкремент операнда на 1 только при установленном флаге `S`.

## Блоки

1. `A[15..0]`.
2. `S flag`.
3. `ADDEND FORM`.
4. `16-bit ADDER`.
5. `CARRY/OVERFLOW`.
6. `Y[15..0]`.

## Как рисовать пошагово

1. Создай файл `R_incs.bdf`.
2. Слева поставь вход `A[15..0]`.
3. Ниже поставь вход `S`.
4. В центре поставь блок `ADDEND FORM`.
5. Внутри подпиши:
   - если `S=0`, то `addend = 0000h`;
   - если `S=1`, то `addend = 0001h`.
6. Справа поставь `ADDER 16+1`.
7. В него заведи:
   - `A[15..0]`;
   - `addend[15..0]`.
8. Из adder выведи:
   - `sum[15..0]`;
   - `carry`.
9. Справа поставь `OVERFLOW LOGIC`.
10. Подпиши:
    - `O = not A15 and S and Y15`.
11. Справа выведи `Y[15..0]`, `C`, `O`.

## Формула на схеме

`Y = A + S`.

# ПРИЛОЖЕНИЕ С. Формирование регистра флагов

## Что должно быть на листе

Логика формирования флагов `Z`, `S`, `C`, `O` и запись их в регистр флагов.

## Блоки

1. `ALU_Y[15..0]`.
2. `ZERO DETECT`.
3. `SIGN BIT`.
4. `CARRY SELECT`.
5. `OVERFLOW SELECT`.
6. `FLAGS REGISTER`.

## Как рисовать пошагово

1. Создай файл `S_flags.bdf`.
2. Слева поставь вход `Y[15..0]`.
3. Ниже поставь входы `carry_raw`, `overflow_raw`, `flag_we`, `clk`, `rst`.
4. Поставь блок `ZERO DETECT`.
5. Внутри подпиши:
   - `Z = 1 when Y = 0000h`.
6. Поставь блок `SIGN BIT`.
7. Подпиши:
   - `S = Y[15]`.
8. Поставь блок `CARRY LOGIC`.
9. Подпиши:
   - `C = carry from SRA/INCS, else 0`.
10. Поставь блок `OVERFLOW LOGIC`.
11. Подпиши:
    - `O = overflow from INCS, else 0`.
12. Справа поставь `FLAGS REGISTER`.
13. В него заведи `Z`, `S`, `C`, `O`.
14. Справа выведи `FR[3..0]`.

## Проверка

Не перепутай порядок. В ПЗ можно подписать просто `Z,S,C,O`, чтобы не спорить о номере бита.

# ПРИЛОЖЕНИЕ Т. Стековое устройство

## Что должно быть на листе

Стек на 7 слов по 16 бит, указатель стека, дешифратор записи и mux чтения.

## Блоки

1. `SP counter [2..0]`.
2. `DECODER 3->7`.
3. `STACK0[15..0]` ... `STACK6[15..0]`.
4. `READ MUX 7->1`.
5. `EMPTY/FULL LOGIC`.

## Как рисовать пошагово

1. Создай файл `T_stack.bdf`.
2. Слева поставь входы:
   - `din[15..0]`;
   - `push`;
   - `pop`;
   - `clk`;
   - `rst`.
3. В центре слева поставь `SP UP/DOWN COUNTER`.
4. Подпиши внутри:
   - `reset SP=7`;
   - `PUSH: SP=SP-1`;
   - `POP: SP=SP+1`.
5. От `SP[2..0]` проведи шину к `DECODER 3->7`.
6. Вертикально поставь 7 регистров:
   - `STACK0`;
   - `STACK1`;
   - ...
   - `STACK6`.
7. От `din[15..0]` проведи общую шину ко всем регистрам.
8. От decoder проведи линии `we0...we6` к регистрам.
9. Справа поставь `READ MUX 7->1`.
10. От каждого `STACKi` проведи `q[15..0]` в mux.
11. На селектор mux заведи `SP[2..0]`.
12. Справа выведи `dout[15..0]`.
13. Внизу поставь `EMPTY/FULL LOGIC`.
14. Подпиши:
    - `empty = 1 when SP=7`;
    - `full = 1 when SP=0`.

## Важная техническая деталь

Стек растет вниз: при `PUSH` сначала используется ячейка `SP-1`, при `POP` читается текущая `SP`, затем `SP` увеличивается.

---

# ПРИЛОЖЕНИЕ У. Исполнительный блок стекового ЗУ

## Что должно быть на листе

Связь команд `PUSH`/`POP` с РОН, стеком и устройством управления.

## Блоки

1. `PUSH/POP opcode decode`.
2. `CONTROL FSM`.
3. `RF read port`.
4. `STACK 7x16`.
5. `RF writeback`.
6. `SP debug/status`.

## Как рисовать пошагово

1. Создай файл `U_stack_exec.bdf`.
2. Слева поставь `IR0[15..0]`.
3. От `IR0[15..8]` проведи в `OPCODE DECODER`.
4. Из декодера выведи:
   - `op_push`;
   - `op_pop`.
5. От `IR0[7..4]` проведи `rn[3..0]`.
6. Поставь блок `CONTROL FSM`.
7. В него заведи `op_push`, `op_pop`.
8. Из него выведи:
   - `stack_push`;
   - `stack_pop`;
   - `rf_we_pop`.
9. Поставь `RF READ PORT`.
10. В него заведи `rn[3..0]`.
11. Из него выведи `rf_a[15..0]`.
12. Поставь `STACK 7x16`.
13. В стек заведи:
    - `din = rf_a`;
    - `push = stack_push`;
    - `pop = stack_pop`.
14. Из стека выведи:
    - `dout[15..0]`;
    - `sp[2..0]`;
    - `empty`;
    - `full`.
15. Справа поставь `RF WRITEBACK`.
16. В него заведи:
    - `din = stack_dout`;
    - `wr_addr = rn`;
    - `we = rf_we_pop`.

## Подпись

`PUSH: Rn -> STACK`, `POP: STACK -> Rn`.

---

# ПРИЛОЖЕНИЕ Ф. Блок кэш-памяти

## Что должно быть на листе

Это самый важный лист. Рисуй его как у товарища: четыре way, у каждого data/tag/valid/age, компаратор, hit/miss, mux данных, FSM, RAM interface.

## Блоки

1. `CPU request register`.
2. `ADDRESS SPLIT`.
3. `WAY0`, `WAY1`, `WAY2`, `WAY3`.
4. Внутри каждого way:
   - `DATA 16x16`;
   - `TAG 16x12`;
   - `VALID 16x1`;
   - `AGE 16x2`.
5. `CMP0...CMP3`.
6. `AND valid`.
7. `OR hit0..3`.
8. `NOT miss`.
9. `MUX 4->1 read data`.
10. `VICTIM SELECT`.
11. `AGE UPDATE`.
12. `CACHE FSM`.
13. `RAM INTERFACE`.

## Как рисовать пошагово

1. Создай файл `F_cache.bdf`.
2. Слева поставь блок `CPU IF`.
3. Внутри подпиши:
   - `cpu_req`;
   - `cpu_we`;
   - `cpu_addr[15..0]`;
   - `cpu_wdata[15..0]`;
   - `cpu_rdata[15..0]`;
   - `cpu_ready`.
4. От `cpu_addr[15..0]` проведи в блок `ADDRESS SPLIT`.
5. Внутри `ADDRESS SPLIT` подпиши:
   - `TAG = A[15..4]`;
   - `SET = A[3..0]`.
6. В центре нарисуй четыре одинаковые группы:
   - `WAY0`;
   - `WAY1`;
   - `WAY2`;
   - `WAY3`.
7. В каждой группе поставь:
   - блок `DATA way i, 16x16`;
   - блок `TAG way i, 16x12`;
   - блок `VALID way i, 16x1`;
   - блок `AGE way i, 16x2`.
8. От `SET[3..0]` проведи шину ко всем DATA/TAG/VALID/AGE блокам.
9. От `TAG[11..0]` проведи шину ко всем компараторам.
10. Справа от каждого way поставь `CMPi TAG==TAGi`.
11. В каждый `CMPi` заведи:
    - `req_tag[11..0]`;
    - `tag_way_i[11..0]`.
12. Рядом с каждым компаратором поставь `AND`.
13. В `AND` заведи:
    - `tag_equal_i`;
    - `valid_i`.
14. Выход подпиши `hit_i`.
15. Все `hit_i` заведи в `OR4`.
16. Выход `OR4` подпиши `cache_hit`.
17. Через `NOT` получи `cache_miss`.
18. Ниже поставь `MUX 4->1 READ DATA`.
19. В него заведи:
    - `data_way0`;
    - `data_way1`;
    - `data_way2`;
    - `data_way3`.
20. Селектор mux подпиши `hit_way[1..0]`.
21. Выход mux проведи к `cpu_rdata[15..0]`.
22. Ниже поставь `VICTIM SELECT`.
23. В него заведи:
    - `valid0..valid3`;
    - `age0..age3`.
24. Выходы:
    - `victim_way[1..0]`;
    - `victim_onehot[3..0]`.
25. Рядом поставь `AGE UPDATE`.
26. Подпиши:
    - `selected age <= 0`;
    - `other valid age <= sat_inc(age)`.
27. Справа поставь `CACHE FSM`.
28. Внутри FSM подпиши состояния:
    - `IDLE`;
    - `WAIT_READ_GRANT`;
    - `WAIT_READ_DATA`;
    - `WAIT_WRITE_GRANT`.
29. В FSM заведи:
    - `cpu_req`;
    - `cpu_we`;
    - `cache_hit`;
    - `cache_miss`;
    - `ram_grant`.
30. Из FSM выведи:
    - `way_we[3..0]`;
    - `ram_req`;
    - `ram_we`;
    - `fill`;
    - `cpu_ready`.
31. Справа снизу поставь `RAM INTERFACE`.
32. Проведи к нему:
    - `ram_req`;
    - `ram_we`;
    - `ram_addr[15..0]`;
    - `ram_wdata[15..0]`;
    - `ram_rdata[15..0]`;
    - `ram_grant`.

## Что точно подписать

1. `4-way associative cache`.
2. `16 sets`.
3. `write-through`.
4. `victim: invalid first, else max AGE`.
5. `TAG=A[15..4]`, `SET=A[3..0]`.

---

# ПРИЛОЖЕНИЕ Х. Блок данных кэша

## Что должно быть на листе

Только datapath кэша: data/tag banks, comparators and mux.

## Блоки

1. `request register`.
2. `address split`.
3. `DATA way0..3`.
4. `TAG way0..3`.
5. `CMP0..CMP3`.
6. `READ DATA MUX 4->1`.

## Как рисовать пошагово

1. Создай файл `H_cache_data.bdf`.
2. Слева поставь `REQ REGISTER`.
3. Внутри подпиши:
   - `addr[15..0]`;
   - `wdata[15..0]`;
   - `we`.
4. Справа от него поставь `ADDRESS SPLIT`.
5. Выведи:
   - `TAG[11..0]`;
   - `SET[3..0]`.
6. В центре нарисуй четыре горизонтальные строки:
   - строка `WAY0`;
   - строка `WAY1`;
   - строка `WAY2`;
   - строка `WAY3`.
7. В каждой строке слева поставь `DATA way i 16x16`.
8. Рядом поставь `TAG way i 16x12`.
9. От `SET` проведи линии ко всем data/tag banks.
10. От `TAG way i` проведи в `CMPi`.
11. От `TAG request` проведи ко всем `CMPi`.
12. Выходы `CMPi` подпиши `hit_i`.
13. Данные `DATA way i` заведи в `MUX 4->1`.
14. Селектор mux подпиши `hit_way`.
15. Справа выведи `cpu_rdata[15..0]`.

## Отличие от приложения Ф

Здесь не нужно подробно рисовать FSM и RAM interface. Это лист только про хранение и выбор данных кэша.

---

# ПРИЛОЖЕНИЕ Ц. Блок флагов кэша

## Что должно быть на листе

Метаданные кэша: valid, tag, age, выбор жертвы и обновление AGE.

## Блоки

1. `VALID memory 4 x 16`.
2. `TAG memory 4 x 16 x 12`.
3. `AGE memory 4 x 16 x 2`.
4. `HIT UPDATE`.
5. `MISS FILL UPDATE`.
6. `VICTIM SELECT`.
7. `METADATA WRITE`.

## Как рисовать пошагово

1. Создай файл `TS_cache_flags.bdf`.
2. Слева поставь три блока:
   - `VALID MEM`;
   - `TAG MEM`;
   - `AGE MEM`.
3. В каждый заведи `set[3..0]`.
4. В `TAG MEM` заведи `req_tag[11..0]`.
5. От `VALID MEM` выведи:
   - `valid0`;
   - `valid1`;
   - `valid2`;
   - `valid3`.
6. От `AGE MEM` выведи:
   - `age0[1..0]`;
   - `age1[1..0]`;
   - `age2[1..0]`;
   - `age3[1..0]`.
7. В центре поставь `VICTIM SELECT`.
8. В него заведи `valid0..3` и `age0..3`.
9. Подпиши внутри:
   - `if invalid exists -> first invalid`;
   - `else max AGE`.
10. Выходы:
    - `victim_way[1..0]`;
    - `victim_onehot[3..0]`.
11. Справа сверху поставь `HIT UPDATE`.
12. Подпиши:
    - `hit way age <= 0`;
    - `other age <= sat_inc`.
13. Справа снизу поставь `MISS FILL UPDATE`.
14. Подпиши:
    - `valid <= 1`;
    - `tag <= req_tag`;
    - `age <= 0`.
15. Все сигналы обновления заведи в `METADATA WRITE`.

## Что важно

Не называй это просто “флаги” в смысле CPU. Это флаги кэша: `VALID` и `AGE`. TAG тоже лучше оставить на схеме, потому что он участвует в достоверности строки.

# ПРИЛОЖЕНИЕ Ш. Блок микро-ЭВМ

## Что должно быть на листе

Общая структура всей микро-ЭВМ: CPU, ROM, cache, RAM, DMA, arbiter, branch predictor.

## Блоки

1. `CPU core`.
2. `ROM command memory`.
3. `Cache 4-way`.
4. `RAM data memory`.
5. `CPU/DMA arbiter`.
6. `DMA controller`.
7. `Branch predictor`.
8. `Debug/status outputs`.

## Как рисовать пошагово

1. Создай файл `SH_microevm.bdf`.
2. Слева в центре поставь `CPU CORE`.
3. Внутри подпиши:
   - `CU`;
   - `RON`;
   - `ALU`;
   - `STACK`;
   - `PC/IR/FR`.
4. Слева снизу или сверху поставь входы:
   - `clk`;
   - `rst`;
   - `dma_start`;
   - `dma_valid`;
   - `dma_data[15..0]`.
5. Сверху справа от CPU поставь `ROM`.
6. Соедини:
   - `CPU -> ROM: rom_addr[15..0], rom_en`;
   - `ROM -> CPU: rom_data[15..0]`.
7. Справа от CPU поставь `CACHE 4-WAY`.
8. Соедини CPU и cache:
   - `cache_req`;
   - `cache_we`;
   - `cache_addr[15..0]`;
   - `cache_wdata[15..0]`;
   - `cache_rdata[15..0]`;
   - `cache_ready`;
   - `cache_hit/miss`.
9. Справа от cache поставь `RAM`.
10. Между cache и RAM поставь `ARBITER`.
11. Снизу поставь `DMA`.
12. Соедини DMA с arbiter:
    - `dma_req`;
    - `dma_grant`.
13. Соедини cache с arbiter:
    - `cpu_req`;
    - `cpu_grant`.
14. От arbiter к RAM проведи итоговые:
    - `ram_en`;
    - `ram_we`;
    - `ram_addr[15..0]`;
    - `ram_wdata[15..0]`.
15. Над CPU поставь `BRANCH PREDICTOR`.
16. Соедини CPU и predictor:
    - `bp_query`;
    - `bp_pc_query[15..0]`;
    - `bp_hist[1..0]`;
    - `bp_pred`;
    - `bp_target[15..0]`;
    - `bp_update`;
    - `bp_taken`;
    - `bp_target_update[15..0]`.
17. Справа сверху поставь `DEBUG/STATUS`.
18. В него выведи:
    - `halt`;
    - `dma_done`;
    - `dbg_state`;
    - `dbg_pc`;
    - `dbg_flags`;
    - `dbg_sp`;
    - `cache_hit/miss`.

## Что важно

Общая схема не обязана показывать внутренности каждого блока. Она должна показать правильное взаимодействие блоков.

# ПРИЛОЖЕНИЕ Щ. Блок управления предсказателя переходов

## Что должно быть на листе

Предсказатель переходов с глобальной историей, таблицей предсказаний и буфером целей.

## Блоки

1. `GHR register [1..0]`.
2. `INDEX LOGIC`.
3. `PHT 16 x 2-bit`.
4. `BTB target 16 x 16`.
5. `BTB valid`.
6. `PREDICT LOGIC`.
7. `UPDATE LOGIC`.
8. `SATURATING COUNTER +/-`.

## Как рисовать пошагово

1. Создай файл `SHCH_branch_predictor.bdf`.
2. Слева поставь входы:
   - `query_valid`;
   - `pc_query[15..0]`;
   - `update_valid`;
   - `pc_update[15..0]`;
   - `actual_taken`;
   - `actual_target[15..0]`.
3. Вверху слева поставь `GHR[1..0]`.
4. В центре поставь `INDEX LOGIC`.
5. В него заведи:
   - `PC[1..0]`;
   - `GHR[1..0]`.
6. Внутри подпиши:
   - `index = PC[1..0] || GHR[1..0]`.
7. Справа от index поставь две памяти:
   - `PHT 16 x 2-bit`;
   - `BTB 16 x 16`.
8. Рядом с BTB поставь `VALID 16 x 1`.
9. Из PHT выведи `pht_state[1..0]`.
10. Из BTB выведи `target[15..0]`.
11. Из VALID выведи `valid`.
12. Справа поставь `PREDICT LOGIC`.
13. В него заведи:
    - `pht_state[1]`;
    - `valid`;
    - `target`.
14. Из него выведи:
    - `pred_taken`;
    - `pred_target[15..0]`.
15. Внизу поставь `UPDATE LOGIC`.
16. В него заведи:
    - `update_valid`;
    - `actual_taken`;
    - `actual_target`;
    - `hist_i`;
    - `pc_update`.
17. Из `UPDATE LOGIC` проведи:
    - `PHT write`;
    - `BTB write`;
    - `VALID write`;
    - `GHR next`.
18. Рядом с PHT нарисуй маленький блок `SAT COUNTER`.
19. Подпиши состояния:
    - `00 strong not taken`;
    - `01 weak not taken`;
    - `10 weak taken`;
    - `11 strong taken`.

## Что важно

В твоём VHDL индекс именно `PC[1..0] || GHR[1..0]`, а не полный PC. На листе это обязательно подписать.

# Итоговая проверка перед печатью

Перед тем как вставлять схемы в ПЗ, пройдись по этому чеклисту:

1. На всех листах фамилия: `Власов Р.Е.`.
2. Нет операций чужого варианта: `ADDC`, `AND`, `NOT`, `ROL`, `CMP`.
3. Нет `NOP`.
4. Везде данные и адреса подписаны как `16 бит`.
5. В РОН ровно `R0...R11`.
6. В стеке есть `STACK0...STACK6`.
7. В кэше четыре way: `WAY0...WAY3`.
8. В кэше есть `TAG`, `VALID`, `AGE`.
9. В предсказателе есть `GHR`, `PHT`, `BTB`.
10. В общей схеме есть `CPU`, `ROM`, `CACHE`, `RAM`, `DMA`, `ARBITER`, `BRANCH PREDICTOR`.
11. На отдельных листах операций есть понятная формула операции.
12. Лист не должен быть пустым: лучше много мелких блоков и шин, чем один большой прямоугольник.
