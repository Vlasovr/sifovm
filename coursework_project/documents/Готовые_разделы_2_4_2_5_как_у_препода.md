# 2.4 Блок выполнения общих операций процессорного ядра

Блок выполнения общих операций процессорного ядра предназначен для организации полного цикла работы микро-ЭВМ при выполнении команды. Он обеспечивает выборку команды из ПЗУ, загрузку регистров команды, декодирование кода операции, выбор исполнительного маршрута, формирование обращений к памяти данных, запуск арифметико-логического устройства, работу со стеком, изменение указателя команд и останов процессора.

В проекте данный блок не выделен в отдельный графический модуль, как в образце преподавателя, а реализован в составе VHDL-сущности `cpu_core`. Внутри `cpu_core` находятся указатель команд `pc_r`, регистры команды `ir0_r` и `ir1_r`, регистровый файл общего назначения, АЛУ, регистр флагов, стек, а также конечный автомат управления `state_r`.

Расположение блока выполнения операций в структуре процессорного ядра показано на рисунке 2.x.

- `state_r` - конечный автомат управления, задающий текущий этап выборки, декодирования и выполнения команды;
- `pc_r` - указатель команды, содержащий адрес первого слова текущей или следующей команды в ПЗУ;
- `ir0_r`, `ir1_r` - регистры команды, в которые загружаются первое и второе 16-разрядные слова команды;
- `cur_opcode_r` - регистр декодированного кода операции;
- `cur_reg_r` - регистр номера РОН, выбранного полем `REG_NUM`;
- `U_RF` - блок регистров общего назначения `R0-R11`;
- `U_ALU` - арифметико-логическое устройство, выполняющее операции `OR`, `NOR`, `SRA`, `INCS`;
- регистр флагов `Z`, `S`, `C`, `O` - хранение признаков результата операций;
- `U_STACK` - стек данных глубиной 7 слов с направлением роста вниз;
- интерфейс ПЗУ команд - выборка двух слов команды;
- интерфейс кэш-памяти данных - выполнение операций чтения и записи данных;
- интерфейс предсказателя переходов - запрос прогноза и обновление таблицы переходов.

В отличие от образца преподавателя, где блок общих операций представлен отдельным графическим BDF-модулем с объединёнными шинами `BUS_IN` и `BUS_OUT`, в данном проекте его функции реализованы в VHDL-сущности `cpu_core`. Поэтому в описании используются реальные порты и внутренние сигналы проекта, а не условные шины из образца.

Далее опишем назначение внешних входных пинов блока:

- `clk_i` - тактовый сигнал процессорного ядра;
- `rst_i` - сигнал синхронного сброса автомата и регистров;
- `rom_data_i[15..0]` - слово команды, считываемое из ПЗУ команд;
- `cache_rdata_i[15..0]` - слово данных, полученное из кэш-памяти;
- `cache_ready_i` - признак завершения операции чтения или записи через кэш;
- `cache_hit_i` - признак попадания при обращении к кэш-памяти;
- `cache_miss_i` - признак промаха при обращении к кэш-памяти;
- `bp_hist_i[1..0]` - история переходов, поступающая от предсказателя;
- `bp_pred_i` - предсказанное направление условного перехода;
- `bp_target_i[15..0]` - предсказанный адрес перехода.

Далее опишем назначение внешних выходных пинов блока:

- `rom_addr_o[15..0]` - адрес слова команды в ПЗУ;
- `rom_en_o` - разрешение обращения к ПЗУ команд;
- `cache_req_o` - запрос операции чтения или записи данных через кэш;
- `cache_we_o` - выбор режима обращения к кэш-памяти: чтение или запись;
- `cache_addr_o[15..0]` - адрес операнда в памяти данных;
- `cache_wdata_o[15..0]` - данные, передаваемые на запись в память;
- `bp_query_o` - запрос к предсказателю переходов;
- `bp_pc_query_o[15..0]` - адрес команды, для которой запрашивается прогноз;
- `bp_update_o` - сигнал обновления предсказателя после фактического выполнения перехода;
- `bp_pc_update_o[15..0]` - адрес команды перехода, по которой обновляется предсказатель;
- `bp_hist_o[1..0]` - история переходов, передаваемая при обновлении;
- `bp_taken_o` - фактический результат условного перехода;
- `bp_target_o[15..0]` - фактический адрес перехода;
- `halt_o` - признак останова выполнения программы;
- `dbg_state_o[4..0]`, `dbg_pc_o[15..0]`, `dbg_ir0_o[15..0]`, `dbg_ir1_o[15..0]` - отладочные выходы текущего состояния, указателя команд и регистров команды;
- `dbg_r1_o-dbg_r7_o` - отладочные выходы регистров общего назначения, используемых в тестовой программе;
- `dbg_flags_o[3..0]` - отладочный выход регистра флагов;
- `dbg_sp_o[2..0]` - отладочный выход указателя стека.

Внутренние управляющие сигналы исполнительной части:

- `rf_we` - разрешение записи в блок РОН;
- `rf_wr_addr[3..0]` - номер регистра, в который записывается результат;
- `rf_rd_a[3..0]`, `rf_rd_b[3..0]` - номера регистров, считываемых из РОН;
- `rf_din[15..0]` - данные, записываемые в выбранный регистр;
- `alu_a_r[15..0]`, `alu_b_r[15..0]` - операнды АЛУ;
- `alu_op_r[2..0]` - код операции АЛУ;
- `alu_y[15..0]` - результат АЛУ;
- `flag_we` - разрешение обновления регистра флагов;
- `stack_push`, `stack_pop` - сигналы занесения слова в стек и извлечения слова из стека;
- `stack_dout[15..0]` - слово, считанное из стека;
- `stack_sp[2..0]` - текущий указатель стека.

Входные и выходные связи блока выполнения операций можно разделить на несколько групп:

- интерфейс ПЗУ команд: `rom_en_o`, `rom_addr_o`, `rom_data_i`;
- интерфейс кэш-памяти данных: `cache_req_o`, `cache_we_o`, `cache_addr_o`, `cache_wdata_o`, `cache_rdata_i`, `cache_ready_i`;
- интерфейс предсказателя переходов: `bp_query_o`, `bp_pc_query_o`, `bp_update_o`, `bp_taken_o`, `bp_target_o`;
- отладочные выходы: `dbg_state_o`, `dbg_pc_o`, `dbg_ir0_o`, `dbg_ir1_o`, `dbg_r1_o-dbg_r7_o`, `dbg_flags_o`, `dbg_sp_o`;
- сигнал останова программы `halt_o`.

Общий алгоритм работы блока задаётся конечным автоматом `state_r`. После сброса автомат переходит к выборке команды. Так как команда имеет фиксированную длину два 16-разрядных слова, выборка всегда выполняется одинаково: первое слово помещается в `IR0`, второе слово помещается в `IR1`. После этого выполняется декодирование кода операции `OPCODE[7..0]`, расположенного в старших разрядах `IR0`.

## 2.4.1 Общий цикл выборки и декодирования команды

Общий цикл выполнения команды начинается с выборки первого слова из ПЗУ команд. В состоянии `S_FETCH0_REQ` на адресный вход ПЗУ передаётся значение `PC`, после чего в состояниях `S_FETCH0_WAIT` и `S_FETCH0_LATCH` слово команды загружается в регистр `IR0`. Затем выполняется выборка второго слова команды: адрес `PC + 1` передаётся в ПЗУ, а считанное слово загружается в регистр `IR1`.

Первое слово команды содержит код операции и номер регистра. Второе слово используется как адрес операнда в памяти данных, адрес перехода или резервное поле. Такой формат делает выборку регулярной: устройство управления всегда выбирает два слова, даже если конкретная команда использует только одно из них.

На временной диаграмме выборки и декодирования видно, что при начальном значении `PC = 0000h` в регистр `IR0` загружается слово `0110h`, соответствующее команде `MOV 0020h, R1`, а в регистр `IR1` загружается адрес операнда `0020h`. После декодирования команда передаётся на выполнение.

## 2.4.2 Маршрутизация данных и обращение к общим шинам

В образце преподавателя для подключения исполнительных блоков к общей шине используются блоки арбитража `CHECK_IN` и `CHECK_OUT`. В разработанной VHDL-модели отдельные графические блоки такого типа не создавались. Их функцию выполняет комбинационная маршрутизация сигналов внутри `cpu_core`, а доступ к ОЗУ данных регулируется кэшем и внешним арбитром шины данных.

Для операций чтения или записи данных процессор формирует сигналы к кэш-памяти:

- `cache_req_o` - запрос обращения к памяти данных;
- `cache_we_o` - направление обмена: чтение или запись;
- `cache_addr_o` - адрес операнда;
- `cache_wdata_o` - данные, записываемые в память;
- `cache_rdata_i` - данные, считанные из памяти;
- `cache_ready_i` - признак завершения обмена.

При промахе кэша обращение передаётся в ОЗУ данных через общий арбитр. Поэтому прямого конфликта между процессором и КПДП на шине ОЗУ не возникает: запросы `REQ_CPU` и `REQ_DMA` обрабатываются арбитром, а разрешения выдаются сигналами `GNT_CPU` и `GNT_DMA`.

## 2.4.3 Команда HLT и зарезервированные коды

В образце преподавателя отдельно рассматривается операция `NOP`. В данной микро-ЭВМ команда `NOP` не реализуется, поэтому вместо неё описывается команда `HLT` и обработка зарезервированных кодов операций.

Команда `HLT` имеет код операции `00h` и предназначена для останова выполнения программы. При декодировании этой команды автомат управления переходит в состояние `S_HALT`. В данном состоянии выборка новых команд прекращается, а на выходе `halt_o` устанавливается активный уровень.

Неиспользуемые коды операций считаются зарезервированными. Если в регистр `IR0` попадает код операции, не входящий в реализованный набор команд, автомат также переводится в состояние `S_HALT`. Это защищает модель от случайного выполнения неопределённой команды и упрощает отладку.

На временной диаграмме завершения программы команда `HLT` определяется по значению `IR0 = 0000h`. После её декодирования сигнал `HALT` принимает активное значение.

## 2.4.4 Команды передачи управления JMP и JZ

Команда `JMP adr` имеет код операции `09h` и выполняет безусловную передачу управления по адресу, заданному вторым словом команды. При выполнении этой команды значение `PC` не увеличивается на два, а заменяется значением `IR1`.

В тестовой программе команда `JMP 001Eh` кодируется словами `IR0 = 0900h` и `IR1 = 001Eh`. После её выполнения следующая выбираемая команда находится по адресу `001Eh`, а команда по адресу `001Ch` пропускается.

Команда `JZ adr` имеет код операции `0Ah` и выполняет условный переход при установленном флаге `Z`. Если `Z = 1`, в `PC` загружается значение `IR1`. Если `Z = 0`, выполнение продолжается линейно, то есть `PC` увеличивается на два.

В тестовой программе перед командой `JZ` выполняется команда `NOR R4, 0025h`, формирующая нулевой результат. Поэтому флаг `Z` устанавливается, и команда `JZ 001Ah` передаёт управление на адрес `001Ah`. Команда по адресу `0018h` не выполняется, что подтверждается неизменным значением регистра `R5`.

При выполнении `JZ` дополнительно обновляется блок предсказания переходов. Процессор передаёт фактический результат перехода через сигналы `bp_update_o`, `bp_taken_o` и `bp_target_o`.

## 2.4.5 Команда MOV adr, Rn: чтение из памяти данных в РОН

Команда `MOV adr, Rn` имеет код операции `01h` и выполняет чтение 16-разрядного слова из памяти данных в выбранный регистр общего назначения. Номер регистра задаётся полем `REG_NUM` первого слова команды, а адрес ячейки памяти задаётся вторым словом `IR1`.

После декодирования команды автомат управления переходит в состояние `S_CACHE_READ`. На адресный вход кэша передаётся значение `IR1`, сигнал записи сбрасывается, а сигнал запроса `cache_req_o` устанавливается в активное состояние. Если требуемое слово находится в кэше, данные сразу выдаются процессору. Если происходит промах, кэш обращается к ОЗУ данных через арбитр, получает слово из памяти, записывает его в выбранную строку кэша и выдаёт процессору.

После появления `cache_ready_i = 1` автомат переходит в состояние `S_RF_WRITE_MEM`, где считанное слово записывается в выбранный регистр общего назначения. Затем команда завершается и автомат переходит к выборке следующей команды.

В тестовой программе команда `MOV 0020h, R1` кодируется словами `IR0 = 0110h` и `IR1 = 0020h`. После её выполнения в регистре `R1` появляется значение `8001h`.

## 2.4.6 Команда MOV Rn, adr: запись из РОН в память данных

Команда `MOV Rn, adr` имеет код операции `02h` и выполняет запись содержимого выбранного регистра общего назначения в память данных. Номер регистра задаётся полем `REG_NUM`, а адрес записи задаётся вторым словом команды `IR1`.

После декодирования команды автомат управления переходит в состояние `S_CACHE_WRITE`. На адресный вход кэша передаётся значение `IR1`, на вход данных кэша передаётся содержимое выбранного регистра, а признак записи устанавливается в активное состояние.

Кэш-память в проекте работает в режиме сквозной записи. Поэтому при записи обновляется строка кэша и одновременно формируется обращение к ОЗУ данных. На временной диаграмме это подтверждается активным импульсом `DBG_RAM_WE`.

В тестовой программе команда `MOV R3, 0030h` кодируется словами `IR0 = 0230h` и `IR1 = 0030h`. К моменту её выполнения в регистре `R3` находится значение `C001h`, поэтому это значение записывается в ячейку ОЗУ с адресом `0030h`.

## 2.4.7 Стековые команды PUSH и POP

Команда `PUSH Rn` имеет код операции `07h` и выполняет занесение содержимого выбранного регистра общего назначения в стек. После декодирования команды автомат переходит в состояние `S_STACK_PUSH`, где активируется сигнал `stack_push`. На вход стека передаётся значение выбранного регистра.

Команда `POP Rn` имеет код операции `08h` и выполняет извлечение слова из стека в выбранный регистр общего назначения. Сначала автомат переходит в состояние `S_STACK_POP`, где активируется чтение из стека. Затем в состоянии `S_RF_WRITE_POP` считанное слово записывается в выбранный регистр.

В тестовой программе команда `PUSH R1` заносит в стек значение `C001h`, а команда `POP R3` извлекает это значение в регистр `R3`. Корректность работы стека подтверждается изменением отладочного сигнала `DBG_SP`: при занесении значение указателя изменяется с `7` на `6`, а при извлечении возвращается с `6` на `7`.

**Рисунок 2.x - Выполнение стековых команд PUSH и POP**

## 2.4.8 Завершение выполнения команды

Большинство команд после выполнения переходят в состояние `S_FINISH`. В этом состоянии автомат завершает текущую операцию, увеличивает `PC` на два и возвращается к выборке следующей команды. Увеличение на два связано с фиксированным двухсловным форматом команды.

Для команд `JMP` и `JZ` значение `PC` изменяется непосредственно в состояниях перехода. Для команды `HLT` возврат к выборке не выполняется: автомат остаётся в состоянии `S_HALT`.

Таким образом, блок выполнения общих операций задаёт единый алгоритм работы процессорного ядра: выборка двух слов команды, декодирование, выбор исполнительного маршрута, выполнение операции, запись результата и переход к следующей команде.

# 2.5 Арифметико-логическое устройство и блок регистров общего назначения

Арифметико-логическое устройство и блок регистров общего назначения образуют вычислительную часть процессорного ядра. Блок РОН хранит промежуточные данные и результаты выполнения команд, а АЛУ выполняет арифметико-логические преобразования над 16-разрядными словами. Результаты операций возвращаются в выбранный регистр общего назначения, а признаки результата фиксируются в регистре флагов.

В разработанной микро-ЭВМ АЛУ выполняет операции `OR`, `NOR`, `SRA` и `INCS`. Дополнительно в пакете команд предусмотрена внутренняя операция `PASS_A`, используемая как нейтральный режим передачи операнда без изменения. Пользовательскими командами являются `OR Rn, adr`, `NOR Rn, adr`, `SRA Rn` и `INCS Rn`.

Состав блока и назначение основных элементов схемы:

- блок регистров общего назначения `U_RF` - хранение операндов и результатов вычислений;
- арифметико-логическое устройство `U_ALU` - выполнение операций `OR`, `NOR`, `SRA`, `INCS`;
- входные регистры `alu_a_r` и `alu_b_r` - фиксация операндов, поступающих на АЛУ;
- регистр кода операции `alu_op_r` - выбор выполняемой операции АЛУ;
- выход результата `alu_y` - передача результата в тракт записи РОН;
- регистр флагов `Z`, `S`, `C`, `O` - хранение признаков результата;
- управляющий сигнал `rf_we` - разрешение записи результата в РОН;
- управляющий сигнал `flag_we` - разрешение обновления регистра флагов.

Назначение входных сигналов вычислительного блока:

- `clk_i` - тактовый сигнал, по которому выполняется запись в РОН и регистр флагов;
- `rst_i` - сброс регистров общего назначения и флагов;
- `rf_a[15..0]` - первый операнд, считанный из выбранного регистра РОН;
- `rf_b[15..0]` - второй операнд, считанный из РОН при необходимости;
- `cache_rdata_i[15..0]` - операнд, считанный из памяти данных через кэш для команд `OR` и `NOR`;
- `flag_s` - текущее значение признака знака, используемое в операции `INCS`;
- `cur_reg_r[3..0]` - номер регистра, участвующего в операции;
- `cur_opcode_r[7..0]` - код выполняемой команды.

Назначение выходных сигналов вычислительного блока:

- `rf_wr_addr[3..0]` - номер регистра, в который записывается результат;
- `rf_din[15..0]` - данные, записываемые в регистровый файл;
- `alu_y[15..0]` - результат операции АЛУ;
- `alu_z`, `alu_s`, `alu_c`, `alu_o` - признаки результата, сформированные АЛУ;
- `dbg_r1_o-dbg_r7_o` - отладочные выходы регистров, используемых в тестовой программе;
- `dbg_flags_o[3..0]` - отладочный выход регистра флагов.

## 2.5.1 Маршрутизация операндов АЛУ

В образце преподавателя для АЛУ отдельно рассматриваются блоки арбитража к общим шинам. В данной VHDL-реализации отдельные графические блоки `CHECK_IN_ALU` и `CHECK_OUT_ALU` не используются. Их функцию выполняют сигналы выбора внутри `cpu_core`.

Первый операнд АЛУ поступает из выбранного регистра общего назначения через выход `rf_a`. Второй операнд зависит от команды. Для операций `OR` и `NOR` он считывается из памяти данных через кэш и поступает на вход АЛУ как `cache_rdata_i`. Для операций `SRA` и `INCS` обращение к памяти не требуется: используется содержимое регистра `Rn`, а для `INCS` дополнительно учитывается значение флага `S`.

После формирования результата АЛУ автомат переходит в состояние `S_ALU_WRITE`. В этом состоянии результат `alu_y` записывается в выбранный регистр общего назначения, а признаки результата записываются в регистр флагов.

## 2.5.2 Блок регистров общего назначения

Блок регистров общего назначения предназначен для хранения промежуточных данных и результатов выполнения команд. В разработанной микро-ЭВМ блок РОН содержит 12 регистров `R0-R11` разрядностью 16 бит. В тестовой программе используются регистры `R1-R7`, значения которых выведены на отладочные шины `DBG_R1-DBG_R7` для контроля работы системы.

Блок РОН реализован как регистровый файл с двумя портами чтения и одним портом записи. Поле номера регистра имеет разрядность 4 бита, поэтому теоретически позволяет адресовать 16 регистров. В данной реализации используются только коды `0-11`, соответствующие регистрам `R0-R11`; коды `12-15` считаются резервными.

Запись в регистр выполняется по активному фронту тактового сигнала при `we_i = 1`. Номер записываемого регистра задаётся шиной `wr_addr_i[3..0]`, а записываемое слово поступает по шине `din_i[15..0]`. Если номер регистра выходит за допустимый диапазон `R0-R11`, запись не выполняется. При `rst_i = 1` содержимое всех регистров сбрасывается в `0000h`.

Чтение данных выполняется по двум независимым адресным входам `rd_addr_a_i` и `rd_addr_b_i`. На выходы `dout_a_o` и `dout_b_o` поступают значения выбранных регистров. Основной канал чтения используется для передачи операнда в АЛУ или данных на запись в память.

Назначение основных элементов блока РОН:

- массив `regs` - хранение двенадцати 16-разрядных регистров общего назначения;
- `wr_addr_i[3..0]` - выбор регистра для записи;
- `rd_addr_a_i[3..0]`, `rd_addr_b_i[3..0]` - выбор регистров для чтения;
- `we_i` - разрешение записи;
- `din_i[15..0]` - входная шина данных;
- `dout_a_o[15..0]`, `dout_b_o[15..0]` - выходные шины чтения;
- `r0_o-r11_o` - отладочные выходы содержимого регистров.

Назначение входных пинов блока РОН:

- `clk_i` - тактовый сигнал записи;
- `rst_i` - сброс содержимого всех регистров;
- `we_i` - разрешение записи;
- `wr_addr_i[3..0]` - адрес регистра, выбранного для записи;
- `rd_addr_a_i[3..0]` - адрес регистра для первого канала чтения;
- `rd_addr_b_i[3..0]` - адрес регистра для второго канала чтения;
- `din_i[15..0]` - слово, записываемое в выбранный регистр.

Назначение выходных пинов блока РОН:

- `dout_a_o[15..0]` - данные первого канала чтения;
- `dout_b_o[15..0]` - данные второго канала чтения;
- `r0_o-r11_o` - отладочные выходы всех двенадцати регистров общего назначения.

## 2.5.3 Структура арифметико-логического устройства

Арифметико-логическое устройство реализовано как 16-разрядный комбинационный блок. На входы АЛУ поступают операнды `A[15..0]` и `B[15..0]`, код выполняемой операции `ALU_OP[2..0]` и текущее значение флага `S`, используемое командой `INCS`.

В состав АЛУ входят логический узел `OR/NOR`, схема арифметического сдвига вправо, сумматор для операции `INCS` и мультиплексор выбора результата. Результат формируется на выходе `Y[15..0]`. Параллельно вычисляются признаки результата: `Z`, `S`, `C` и `O`.

Назначение входных пинов АЛУ:

- `a_i[15..0]` - первый операнд;
- `b_i[15..0]` - второй операнд;
- `flag_s_i` - вход текущего значения флага `S` для операции `INCS`;
- `op_i[2..0]` - код выполняемой операции.

Назначение выходных пинов АЛУ:

- `y_o[15..0]` - результат операции;
- `z_o` - признак нулевого результата;
- `s_o` - признак знака результата;
- `c_o` - признак переноса или вытесненного младшего бита при сдвиге;
- `o_o` - признак переполнения.

Таблица 2.x - Кодирование операций АЛУ

| Код `ALU_OP[2..0]` | Операция | Назначение |
|---|---|---|
| `000` | `PASS_A` | передача операнда `A` без изменения |
| `001` | `OR` | поразрядное логическое ИЛИ |
| `010` | `NOR` | инверсия результата поразрядного ИЛИ |
| `011` | `SRA` | арифметический сдвиг вправо |
| `100` | `INCS` | инкремент при активном флаге `S` |

## 2.5.4 Блок операции OR

Команда `OR Rn, adr` выполняет побитовое логическое ИЛИ между содержимым регистра `Rn` и словом памяти данных по адресу `adr`. Первый операнд поступает из регистрового файла, а второй считывается из памяти данных через кэш.

После декодирования команды процессор переходит в состояние `S_CACHE_READ`, получает слово памяти и передаёт его на второй вход АЛУ. Затем задаётся код операции `ALU_OR`. Результат вычисляется по выражению:

`Y = A OR B`.

После выполнения операции результат записывается обратно в регистр `Rn`. Флаг `Z` устанавливается при нулевом результате, флаг `S` копирует старший бит результата. Флаги `C` и `O` для логической операции сбрасываются.

В тестовой программе команда `OR R2, 0022h` используется для проверки логического тракта АЛУ и обмена с памятью данных.

**Рисунок 2.x - Выполнение операции OR**

## 2.5.5 Блок операции NOR

Команда `NOR Rn, adr` выполняет инверсию результата побитового ИЛИ регистра `Rn` и слова памяти данных. Как и для команды `OR`, первый операнд поступает из регистра общего назначения, а второй операнд считывается из памяти через кэш.

Результат операции формируется по выражению:

`Y = NOT(A OR B)`.

Полученное значение записывается обратно в выбранный регистр общего назначения. Флаги `Z` и `S` формируются по результату операции, а флаги `C` и `O` сбрасываются.

В тестовой программе команда `NOR R4, 0025h` используется для формирования нулевого результата. После её выполнения устанавливается флаг `Z`, что затем проверяется командой условного перехода `JZ`.

**Рисунок 2.x - Выполнение операции NOR**

## 2.5.6 Блок операции SRA

Команда `SRA Rn` выполняет арифметический сдвиг содержимого регистра `Rn` вправо на один разряд. Второе слово команды выбирается из ПЗУ в рамках общего формата, но при выполнении не используется.

При арифметическом сдвиге старший бит исходного операнда сохраняется, поэтому знак числа не изменяется. Остальные биты сдвигаются вправо, а младший вытесненный бит записывается во флаг `C`.

Для операнда `A` результат формируется следующим образом:

`Y(15) = A(15)`;

`Y(i) = A(i+1), где i = 0...14`.

В тестовой программе после команды `MOV 0020h, R1` в регистре `R1` находится значение `8001h`. После выполнения `SRA R1` оно преобразуется в `C000h`, а вытесненный младший бит записывается во флаг `C`.

**Рисунок 2.x - Выполнение операции SRA**

## 2.5.7 Блок операции INCS

Команда `INCS Rn` выполняет инкремент выбранного регистра на значение флага `S`. В отличие от обычного инкремента, ко входу сумматора подаётся не постоянная единица, а текущее значение флага знака.

Результат операции описывается выражением:

`Y = A + S`.

Если `S = 0`, содержимое регистра не изменяется. Если `S = 1`, значение регистра увеличивается на единицу. После вычисления результат записывается обратно в выбранный регистр, а флаги `Z`, `S`, `C` и `O` обновляются по результату операции.

В тестовой программе команда `INCS R1` выполняется после `SRA R1`. Так как после сдвига значение `R1 = C000h` имеет установленный старший бит, флаг `S` равен единице. Поэтому команда `INCS R1` изменяет значение регистра на `C001h`.

## 2.5.8 Формирование регистра флагов

Регистр флагов фиксирует признаки результата арифметико-логических операций. В проекте используются четыре флага:

- `Z` - признак нулевого результата;
- `S` - признак знака результата;
- `C` - перенос или вытесненный бит;
- `O` - признак переполнения.

Флаг `Z` устанавливается, если результат АЛУ равен `0000h`. Флаг `S` повторяет старший бит результата. Флаг `C` при операции `SRA` получает младший вытесненный бит исходного операнда, а при `INCS` используется как перенос из старшего разряда. Флаг `O` используется для фиксации переполнения при выполнении `INCS`; для логических операций и сдвига он сбрасывается.

Таблица 2.x - Реализация операций АЛУ и обновление флагов

| Операция | Аппаратное выражение | Запись результата | Обновление флагов |
|---|---|---|---|
| `OR Rn, adr` | `Y = A OR B` | `Rn <- Y` | `Z = (Y = 0)`, `S = Y15`, `C = 0`, `O = 0` |
| `NOR Rn, adr` | `Y = NOT(A OR B)` | `Rn <- Y` | `Z = (Y = 0)`, `S = Y15`, `C = 0`, `O = 0` |
| `SRA Rn` | `Y15 = A15`, `Yi = A(i+1)` | `Rn <- Y` | `Z = (Y = 0)`, `S = Y15`, `C = A0`, `O = 0` |
| `INCS Rn` | `Y = A + S` | `Rn <- Y` | `Z = (Y = 0)`, `S = Y15`, `C` - перенос, `O` - переполнение |

Таким образом, арифметико-логическое устройство и блок РОН обеспечивают выполнение всех вычислительных команд проектируемой микро-ЭВМ. Команды `OR`, `NOR`, `SRA` и `INCS` проверяют логическую обработку, арифметический сдвиг, условный инкремент и корректное формирование флагов.
