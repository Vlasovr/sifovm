# Подготовка к защите ЛР5-8

## Общая логика комплекта

Все четыре лабораторные работы показывают отдельные узлы будущей микро-ЭВМ. Поэтому везде используются 16-разрядные данные, согласованные коды команд и единый стиль верхних схем. На защите удобно объяснять не как набор разрозненных файлов, а как последовательное наращивание процессорной подсистемы:

1. ЛР5 добавляет исполнительный блок АЛУ.
2. ЛР6 добавляет стек и стековые команды.
3. ЛР7 показывает разделение общей шины между несколькими ведущими устройствами.
4. ЛР8 добавляет ускоряющую память между процессором и основной памятью.

Главная линия защиты: каждое устройство сначала спроектировано как набор аппаратных блоков, затем для него определены входы и выходы, алгоритм работы, контрольные ситуации и результаты проверки.

## ЛР5. АЛУ

Что реализовано:

- `CMP`: сравнение двух 16-разрядных операндов через вычитание `A-B` без записи разности как основного результата;
- `NOR`: инверсия результата поразрядного сложения по ИЛИ;
- `SRA`: арифметический сдвиг вправо с сохранением знакового разряда;
- блок флагов `Z`, `S`, `C`, `O`.

Как читать схему:

- код операции поступает в блок управления;
- блок управления выбирает одну из трех функциональных ветвей;
- ветви `CMP`, `NOR`, `SRA` вычисляют результат параллельно;
- мультиплексор результата передает наружу выбранное значение;
- блок флагов формирует признаки нуля, знака, переноса/заема и переполнения.

Контрольные примеры:

| Ситуация | Ожидаемый смысл |
|---|---|
| `CMP 1234h, 0020h` | `A>B`, заем отсутствует |
| `CMP 2222h, 2222h` | операнды равны, `Z=1` |
| `CMP 0010h, 0020h` | `A<B`, фиксируется заем и отрицательный признак |
| `NOR 0F0Fh, F0F0h` | результат `0000h`, `Z=1` |
| `SRA 8001h` | результат `C000h`, младший вытолкнутый бит попадает в `C` |

Типовые вопросы:

| Вопрос | Короткий ответ |
|---|---|
| Почему сравнение реализовано через вычитание? | Сравнение чисел удобно свести к `A-B`: по нулевому результату видно равенство, по заему и знаку - отношение операндов. |
| Почему для `SRA` старший бит повторяется? | Это арифметический сдвиг, он сохраняет знак числа в дополнительном коде. |
| Где формируются флаги? | После выбора результата, чтобы признаки соответствовали именно выполненной операции. |
| Чем `NOR` отличается от `OR`? | `NOR` сначала получает поразрядное ИЛИ, затем инвертирует все биты результата. |

## ЛР6. Стек

Что реализовано:

- стек на 7 слов по 16 бит;
- команды `PUSH`, `POP`, `PUSH_ALU`;
- указатель `SP`, который показывает последнюю занятую ячейку;
- признаки `empty`, `full`, `overflow`, `underflow`.

Как работает указатель:

- после сброса стек пуст, `SP=7`;
- первый `PUSH` записывает данные в ячейку `0`, затем `SP=0`;
- следующий `PUSH` записывает данные в ячейку `1`, затем `SP=1`;
- при заполнении семи ячеек `SP=6`, признак `full=1`;
- `POP` читает текущую вершину, затем возвращает указатель на предыдущую занятую ячейку;
- после чтения последнего элемента стек снова пуст, `SP=7`.

Контрольные примеры:

| Ситуация | Ожидаемый смысл |
|---|---|
| `PUSH 1111h`, `PUSH 2222h`, затем `POP` | первым читается `2222h`, выполняется LIFO |
| `PUSH_ALU 000Fh` | в стек заносится результат от АЛУ, а не данные из регистра |
| восьмой `PUSH` | данные не записываются, появляется `overflow` |
| `POP` из пустого стека | данные не меняются, появляется `underflow` |

Типовые вопросы:

| Вопрос | Короткий ответ |
|---|---|
| Почему пустой стек имеет `SP=7`? | Это служебное значение за пределом семи реальных ячеек `0..6`; оно удобно отличает пустое состояние. |
| Почему полный стек имеет `SP=6`? | Последняя реальная ячейка имеет индекс 6, значит все семь ячеек заняты. |
| Как проверяется LIFO? | Последним записанное слово должно быть считано первым. |
| Зачем нужны `overflow` и `underflow`? | Они запрещают незаметную потерю данных при записи в полный стек и чтении из пустого. |

## ЛР7. Арбитраж шин

Что реализовано:

- четыре ведущих устройства;
- один ведомый приемник;
- одна 16-разрядная общая шина данных;
- централизованный параллельный арбитр;
- фиксированный квант времени: один слот удерживается два такта.

Как работает арбитр:

- каждое ведущее устройство выставляет собственный запрос `REQ`;
- арбитр циклически перебирает слоты `0, 1, 2, 3`;
- если в текущем слоте запрос активен, выдается соответствующий `GNT`;
- мультиплексор пропускает данные только выбранного ведущего;
- ведомое устройство фиксирует данные при активной передаче.

Контрольные примеры:

| Ситуация | Ожидаемый смысл |
|---|---|
| несколько запросов одновременно | обслуживается только ведущий текущего слота |
| запроса в текущем слоте нет | шина остается свободной до следующего слота |
| слот удерживается два такта | квант времени фиксирован, переключение не происходит каждый такт |
| активен один `GNT` | конфликт на общей шине исключен |

Типовые вопросы:

| Вопрос | Короткий ответ |
|---|---|
| Почему арбитраж централизованный? | Решение принимает один общий блок, поэтому нет спора между ведущими устройствами. |
| Почему подключение параллельное? | У каждого ведущего есть собственная линия запроса и собственная линия разрешения. |
| Как исключается конфликт на шине? | Мультиплексор подключает к общей шине только источник, которому выдано разрешение. |
| Что дает фиксированный квант? | Каждое устройство получает предсказуемое окно обслуживания. |

## ЛР8. Кэш-память

Что реализовано:

- кэш прямого отображения;
- 8 строк по одному 16-разрядному слову;
- индекс строки берется из `A2..A0`;
- тег хранится по старшим битам адреса;
- признак достоверности `valid`;
- сквозная запись `write-through`.

Как работает чтение:

- адрес делится на тег и индекс строки;
- по индексу выбирается единственная строка кэша;
- тег выбранной строки сравнивается с тегом адреса;
- если тег совпал и `valid=1`, происходит попадание;
- при промахе слово читается из основной памяти и загружается в выбранную строку.

Как работает запись:

- данные обязательно уходят в основную память;
- если адрес уже есть в кэше, соответствующая строка обновляется;
- если адреса в кэше нет, строка может быть загружена при последующем чтении.

Контрольные примеры:

| Ситуация | Ожидаемый смысл |
|---|---|
| первое чтение `0010h` | промах, загрузка из основной памяти |
| повторное чтение `0010h` | попадание |
| запись `0010h = ABCDh` | обновляется основная память и строка кэша |
| чтение `0018h` | тот же индекс строки, другой тег, возникает замещение |
| повторное чтение `0010h` после `0018h` | снова промах, потому что строка была занята другим тегом |

Типовые вопросы:

| Вопрос | Короткий ответ |
|---|---|
| Почему кэш называется прямого отображения? | Каждый адрес может попасть только в одну строку, выбранную индексными битами. |
| Зачем нужен тег? | Индекс выбирает строку, а тег проверяет, действительно ли в ней лежит нужный адрес. |
| Зачем нужен `valid`? | После сброса строки пустые, и совпадение тега само по себе еще не должно считаться попаданием. |
| Что дает сквозная запись? | Основная память всегда содержит актуальное значение после операции записи. |
